主题色重设计 · 请人工选择

先把现有两套主题（light / dark）全量体检了 → 找出 8 个问题 → 用「阈值求解」生成 3 个候选方向（而不是手调色）→ 下面可以实时换肤预览、并逐项拍板。
所有对比度都是 WCAG 公式现场算出来的，阈值：正文/金额文字 4.5:1、大字号 3:1、非文字图形 3:1、深色主题语义色 7:1。

1现状体检

数值来自 lib/core/theme/app_theme_tokens.dart 与 app_theme.dart（解析自源码，不是抄的）。

判定问题实测与说明
严重深色实心按钮白字只有 2.05:1深色 primary #FF9A88 + 白字 = 2.05:1（浅色 3.47:1）。实心按钮白字要 4.5:1 —— 深色下几乎读不清，是本次最严重的一项。
严重选中 chip：同色叠同色 3.03:1chip 选中态用 primary 12% 底 + primary 文字 = 3.03:1（secondary 同理 2.66:1）；「同色系淡底 + 同色文字」天然不达标。
严重品牌红与支出红只差 11.5°品牌 #E45F4F(6.4°) 与支出 #CD323F(355°) 夹角 11.5°；品牌↔tertiary 21.6°。同一屏里两个红，用户分不清「强调」还是「支出」。
严重深色的「信用」色与浅色不同族浅色 credit #8757BE（紫 268°）、深色 credit #FFC27A（橙 32°）—— 同一个语义在两种主题下是两种颜色，且深色里品牌橙/信用橙/警示黄三者只差 11°~15°。
严重Hero 琥珀字 #FFD9A0 对比不足净资产卡「负债」用的琥珀在渐变端点上只有 3.44:1（需 4.5:1）；品牌渐变上也是 3.43:1。
待改品牌渐变三档几乎同色品牌渐变 #C25144 → #C0515C → #BE506A 色相跨度仅 9°，观感偏「糊」；而被认可的净资产卡跨度 93°——这就是它好看的原因。
严重分类自定义色板在两种主题下都有不达标色色板 15 色实测：浅色主题 6/15 不达 3:1（#F97316 2.80、#F59E0B 2.15、#EAB308 1.92、#0EA5E9 2.77、#06B6D4 2.43、#10B981 2.54），深色主题 2/15 不达 3:1（#475569 2.21、#334155 1.62）。同一个色板不可能同时服务两种主题：橙黄系在浅色下发虚、深蓝灰在深色下消失。
严重「同色文字叠同色淡底」系统性地卡在 4.3:1语义色 12% 淡底 + 同色文字：浅色主题实测 4.25:1（现状 chip 选中态 3.03:1 更糟）。扫了透明度梯度：6% → 4.67、8% → 4.54、10% → 4.40、12% → 4.25、16% → 4.00。要过 4.5 必须 ≤8%，而现在通用的写法是 12%~14%。
待改淡底没有梯度 token全仓 270 处给颜色加透明度（6%~94% 都有），但没有任何「淡底梯度」token —— 每处都在手写 alpha，层级和达标情况全靠自觉。这正是上一批 UI 统一时只统一了圆角/间距、没统一颜色的后遗症。
严重图表色板未 token 化四张图各自写了一份调色板（顺序都不同），并直接用 Material 原色 Colors.orange / teal / indigo / pink / cyan —— 深色模式下不跟随主题（如 #3F51B5 压在深底上过暗）。
待改themeSeedColor 是死配置user_preferences 有列、注册时写默认值，但 app_theme.dart 从未读取 → 换主题色毫无效果。要么接回主题，要么删列。
已达标已经做得对的部分浅色语义色 4.55~5.09:1、深色 8.15~11.72:1 全部达标；暖中性三色（#FFF8F2 / #FFF0E5 / #EAD8CC）色相挤在 4° 内、只靠明度分层 —— 这是「暖」且耐看的根基，三个方案都保留。

2三个候选方向

每个方向的每个颜色都由「固定色相 + 解明度」得到：色相保证语义不撞车，明度保证对比度达标。三个方向的浅色语义色都落在 4.55~4.7:1、深色 7.5~12:1。

1 暖橙 · 修正版 保身份

把品牌从「红」挪到「暖橙」，支出红就独占红色语义；暖米底原样保留。

深色 · 品牌 / 语义 / 中性

  • 气质最接近现状，老用户无感切换

  • 所有可读性阈值一次达标

2 靛蓝 · 冷品牌 最清晰

品牌走蓝紫，红=支出、绿=收入、蓝=品牌，三种语义在色相环上各占一方。

  • 品牌↔支出 120°+，误读概率最低
  • 图表色板从品牌色相推导，天然错开

  • 气质变化最大，不再是「暖米记」
  • 与净资产卡的紫（285°）有点近，需要靠明度区分

品牌走深青、中性底转冷灰绿，整体低饱和，适合长时间记账。

3三条修法配方（与选哪个方向无关，都建议做）

这三条是「怎么做」，不是「选哪个颜色」。三条都有实测数字支撑。

R1 · 选中态改用 container 配对

选中态不要用「primary 淡底 + primary 文字」，改用 M3 的 primaryContainer 底 + onPrimaryContainer 文字。

现状 chip 选中态3.03:1
方向 1 配对10.71 / 9.13:1
方向 2 配对13.29 / 10.27:1
方向 3 配对8.42 / 8.21:1

（浅色 / 深色两档；本页所有 mockup 的选中态已按这个配方渲染）

R2 · 淡底统一 ≤8%（建议 6%）

同色文字叠同色淡底的实测梯度，浅色主题（阈值 4.5）：

淡底最差对比度
6%4.67 ~ 4.75过
8%4.54 ~ 4.58刚好过
10%4.40 ~ 4.45不过
12%（现状常用）4.25 ~ 4.32不过
16%4.00 ~ 4.06不过

建议新增一组 AppTints（6 / 10 / 14 / 24 / 40%），文字叠底一律用 6% 档。

R3 · 分类色改成「用户选色相」

现在的 15 色色板在两种主题下都有一批不达标。做法：用户只挑色相（12 档），明度由主题求解（和语义色同一套求解器）。

浅色主题不达标6/15 · 橙黄与青绿系
深色主题不达标2/15 · 深蓝灰系
改后两主题全部 ≥3:1

代价：老数据里的分类色需要映射到最近的色相（一次性迁移，存储仍存 hex 以便回退）。
