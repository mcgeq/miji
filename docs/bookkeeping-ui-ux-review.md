# 记账模块 UI / 布局审查与优化清单

> 审查日期：2026-10-11
> 范围：`lib/features/bookkeeping/presentation/` 全部面板 + `features/shell` 入口层
> 说明：文中行号为审查时的快照，定位时请以「函数名 / 代码片段」为准。

---

## 一、结论速览

记账模块的**功能完整度已经很高**，主要矛盾不在「缺功能」，而在**同一批信息在多处重复铺开，导致高频动线的首屏被挤压**。

按「投入产出比」排序，最值得动的是四件事：

| # | 问题 | 影响 |
|---|---|---|
| 1 | 流水页首屏被 6 段控制区占掉约 270–500px | 每次打开要先滚才看到第一笔 |
| 2 | 自动记账页 3 层横幅 + 常驻分期预览压在模板列表之上 | 首屏经常「只见横幅不见模板」 |
| 3 | 「新增」入口散落 5 处（FAB 8 动作 + 4 个页面各自的 ＋） | 用户不知道哪个才是「对的那个」 |
| 4 | 空状态 CTA 多为纯图标、且不区分「无数据 / 筛选无结果」 | 首次使用与筛选落空时都无从下手 |

## 二、信息架构现状

### 2.1 入口层级

```
底部导航（移动端 4 项，中间嵌 FAB）
 ├─ 打卡 / 记账 / 首页 / 健康
 └─ FAB「快速新增」→ 4×2 网格 8 个动作
      支出 · 收入 · 转账 · 任务 · 账户 · 分期 · 预算 · 计划

记账页（BookkeepingPage）
 ├─ 顶部：账本选择器（仅非 compact 显示；移动端由 Shell 顶栏提供）
 ├─ 一级 Tab（常驻 4 个）：流水 · 账户 · 预算 · 统计
 └─ 二级 Tab（更多）：      分类 · 分期 · 自动记账 · 提醒
```

证据：`bookkeeping_page.dart:715-728`（`_primaryPanels` / `_morePanels`）、`app_shell_page.dart:71-78`（FAB）、`money_quick_action_fab.dart:41-50`（8 个动作）。

### 2.2 值得注意的两个「反直觉」默认

1. **进记账页默认落在「账户」，不是「流水」**。`bookkeeping_page.dart:53` `_selectedPanel = _BookkeepingPanel.accounts`，且 `_panelFromSection` 的兜底也是 accounts（`:769`）。而 Tab 栏第一个是「流水」。高频页面不是默认页，用户每次进来都要多点一下。
2. **FAB 的 8 个动作与页面内的 ＋ 重复**。FAB 里已有账户 / 分期 / 预算 / 支出 / 收入 / 转账，而账户页、预算页、分期页、自动记账页又各自有一个 ＋。

## 三、问题清单

### P0 · 影响最高频动线

#### P0-1 流水页首屏被控制区挤压

**现象**：列表之前依次堆叠 6 段（搜索框 → 操作行 → 状态 chips → 日期 chips → 汇总条 → 各类 banner），粗算抹掉 270px；若命中「待确认 banner / 账户月度汇总 / 预算 banner」，可再涨 200px+。手机上第一笔流水常在屏幕下半部甚至第二屏才出现。

证据：`money_transactions_section.dart:258-419`（`Column` 的 16 段结构），其中
- 搜索框 `:263-278`
- 操作行 `:280-376`
- 状态 chips `:378-384`
- 日期 chips `:402-407`
- 汇总条 `:419`
- 三类条件 banner `:409-416`、`:440-446`、`:447-453`

**建议**：
- 把「状态 chips + 日期 chips」合并进一个可展开的「筛选条」（默认只显示当前生效项），或直接并入高级筛选抽屉。
- 汇总条改成**贴底吸底**（`SliverPersistentHeader` pinned），不再占用列表上方空间。
- 从账户 / 预算下钻进来时（`_transactionFilterContext != null`），把上下文横幅做成一枚可关闭的小 chip，而不是整条 banner。

#### P0-2 每次改筛选整屏闪骨架

**现象**：任意筛选变更都会清空列表并置 `_isLoadingInitial = true`，列表区瞬间变成骨架，**点一下 chip 页面就白一下**。

证据：`_refreshFromFilterChange`（`money_transactions_section.dart:1029-1040`），`_setTypeFilter` / `_setStatusFilter` / 日期 chips 均调用它；骨架渲染在 `:480-482`。

**建议**：筛选变更改为**保留旧列表 + 顶部细进度条 / 列表降透明度**，仅在首次进入时用骨架。

#### P0-3 空状态不区分「无数据」与「筛选无结果」

**现象**：`emptyBuilder` 无条件注入，无论是否带筛选，都显示同一条「还没有流水 / 可以从快速新增记录支出、收入或转账」。用户叠加了账户+分类+日期后查不到，仍然被建议「快速新增」。

证据：`money_transactions_section.dart:496-497`、`_EmptyTransactionsPanel` `:3606-3626`；已有 `_hasActiveFilters`（`:128-140`）与「清除筛选」逻辑（`:1521-1555`）可复用。

**建议**：空态分流——有筛选时显示「没有符合条件的流水」+「清除筛选」主按钮；无筛选时才显示引导记账。

#### P0-4 交易卡片日期与分组头重复

**现象**：分组头已经给了「今天 / 昨天 / X月X日」，卡片内又固定渲染一次 `MM-DD HH:mm`。同一天被表达了两次，卡片白白多占一行。

证据：分组头 `money_transactions_section.dart:506-518`、`:3578-3586`；卡片日期 `transaction_card.dart:130`、`:419-426`。

**建议**：卡片内日期改为**只有时间**（`HH:mm`），跨天信息交给分组头；或在同天分组内完全隐藏日期行。

#### P0-5 滑动手势零提示、动作钮触控目标偏小

**现象**：编辑 / 退款 / 删除的唯一「快」入口是左滑，但动作面板默认收起、无任何视觉提示，新用户发现不了。且 4 个动作纵向堆在一列 58px 宽的抽屉里，卡片矮时单钮被压到约 20px。

证据：`transaction_card.dart:68-103`（`AppSwipeAction` 最多 4 个）；`app_list_item.dart:107`（`actionPaneWidth = 58`）、`:248-285`（按高度均分，`:266` 有 40px 上限 clamp）。

**建议**：
- 首次进入给一次「左滑可操作」的轻提示（类似 iOS 的一次性手势引导）。
- 卡片右侧常驻一个 `⋯`（就是详情入口），把「复制 / 退款 / 删除」收进去，让滑动退化为「快捷方式」而非唯一路径。
- 动作钮补足最小 44×44 的命中区（外层包 `SizedBox`，视觉可保持 32）。

### P1 · 跨页一致性与信息架构

#### P1-1 自动记账页：横幅 + 分期预览压住模板列表

**现象**：页面自上而下是「搜索框 → 冲突横幅 → 接管失效横幅 → 分期还款计划预览 → 新增按钮 → 模板列表」。三层提示可同时出现（`:96`、`:99`、`:102`），模板列表首屏经常看不见。代码注释本身也承认「常驻展开会把自动记账列表挤出屏幕」（`:568-569`）。

**补充问题**：
- 折叠态只显示数量「N 个 · 到期自动入账」（`:608-646`），**没有「最近一期到期日」**这类真正有用的信息。
- 展开是硬分支 `if (_expanded)`（`:647`），只有箭头有动画，面板高度瞬跳。
- 该预览与「分期」Tab 的列表 / 明细**职责重叠**（`:562-800`）。

**建议**：
- 把该预览降级为**列表底部的一行「相关」链接**（→ 跳转分期 Tab），或整体移除，交给分期 Tab。
- 三层横幅合并成一个可折叠「提醒区」，默认折叠。
- 展开体加 `AnimatedSize`，并补上「最近一期到期日」。

#### P1-2 「新增」入口散落 5 处

**现象**：FAB 的 8 个动作已覆盖账户 / 分期 / 预算 / 支出 / 收入 / 转账，但账户页（`:1152-1158`）、预算页（`:166-171`）、分期页（`:294-301`）、自动记账页（`:106-113`）又各有一个 ＋。且**样式与位置都不统一**：账户页是混在 header 里的 plain 图标，其余是行内居右的 filled ＋。

**建议**：统一为「页面内 ＋ 只负责本页实体，FAB 只管流水类动作」的单一规则，并把 ＋ 的样式抽成同一个组件。

**已处理（批次三）**：四个页面的 ＋ 统一为 `AppIconActionVariant.filled` + `Icons.add_rounded`（账户页原是同排唯一的 `plain`，自动记账页原用 `event_repeat_rounded`）。**FAB 的九宫格没动**——它跨页面可用，砍掉账户 / 预算 / 分期三个入口是能力缩减，不属于「样式统一」的范围，单列为产品决策。抽组件这件事也没做：四处 tooltip 各异、图标相同，包一层只是多一层间接。

#### P1-3 双操作入口重复，左滑项过多

**现象**：
- 预算卡片：左滑 **5 项**（查看流水 / 预算历史 / 预算分配 / 编辑 / 删除），同时 `⋯` 菜单又有 4 项。
- 账户卡片：左滑 3 项 + `⋯` 菜单 **6 项**。
- 代码注释自己都承认「手机一次只见 2~3 个」（`budget_card.dart:233-234`）。

证据：`budget_card.dart:66-104`、`:235-295`；`money_accounts_section.dart:1535-1561`、`:1136-2180`。

**建议**：左滑只保留 2 个高频（编辑 / 删除），其余全部收进 `⋯`；或反过来——只保留 `⋯`，去掉滑动。**二选一，不要并存**。

**已处理（批次三）**：按「保留 2 个高频」执行。

- 预算卡片左滑 `5 → 2`（编辑 / 删除）。去掉的三项都有更近的入口：查看流水本来就是卡片里的常驻文字按钮，预算历史与分配设置在 `⋯` 菜单里。
- 账户卡片左滑 `3 → 2`（编辑 / 删除）。「停用 / 启用」收进 `⋯`（菜单里原本就有这一项，属于纯重复）。
- 没有做「去掉滑动只留菜单」那一版：左滑是不要钱的快捷方式，删掉它反而让高频的编辑 / 删除变远。

#### P1-4 术语不统一 —— 已处理（含两处原判错的更正）

> 复核时发现本表原来有两行把**不同概念**说成了同一个东西，先更正，再给统一结果。

| 概念 | 原来的叫法 | 统一为 | 落点 |
|---|---|---|---|
| 预算下的**分配项**（把预算分摊到子类 / 成员） | 「子分配」/「分配项」/「分配」 | **分配** | `budget_card.dart`：`N 项分配`、菜单项 `分配设置` |
| 预算周期内**被预占的额度**（自动记账 / 分期） | 「未来义务」 | **未来义务**（维持不动） | `budget_commitment_sheet.dart`、`budget_card.dart` 的「已预留 N 项未来义务」 |
| 交易类型（支出 / 收入 / 转账） | 筛选抽屉里叫「类型」 | **交易类型** | `money_transactions_section.dart` 筛选抽屉 |
| 统计口径（收支 / 支出 / 收入） | 统计页筛选叫「类型」 | **统计类型** | `money_statistics_section.dart` |
| 账户类型（储蓄 / 信用卡 / …） | 统计页「账户类型」vs 账户页「类型」 | **账户类型** | `money_accounts_section.dart`（宽度 120→148）、`money_statistics_section.dart` |
| 预算追踪类型（支出限额 / 收入目标） | 预算页筛选叫「类型」 | **追踪类型** | `money_budgets_section.dart`（宽度 132→146） |
| 支付渠道（现金 / 微信 / 支付宝 / …） | 统计页「渠道」vs 流水筛选「支付渠道」 | **支付渠道** | `money_statistics_section.dart`、`money_transactions_section.dart` |
| 分期 × 自动记账冲突 | 「…会记两遍」/「…会被记两遍账」 | **「检测到 N 处重复登记，同一笔还款会被记两遍账」** | 两个页面同一句话 |

**两处更正**：

1. **「子分配」与「未来义务」不是同一个东西**。前者是预算的分摊项（`MoneyBudgetAllocation`），后者是被自动记账 / 分期预占的额度（`MoneyBudgetCommitment`）。原表把它们并列成「同一个东西的三种叫法」是错的；真正需要收敛的是分配项内部（子分配 / 分配项 → 分配）。四个筛选下拉都叫「类型」但含义各异，才是这一节真正的问题。
2. **「支付渠道」那行也不成立**。预算页那个 `label: '类型'`（`money_budgets_section.dart:665`）绑的是 `MoneyBudgetTrackingType`（支出限额 / 收入目标），跟支付渠道毫无关系。真正的不一致在统计页（「渠道」）与流水筛选抽屉（「支付渠道」）之间。

**没做的一项**：原建议「冲突提醒只保留一处 UI（收进提醒中心或全局角标）」。这条改为**保留两处**——分期页与自动记账页是两条独立进入路径，从哪边进来都该看到提示，代价只是两行文案，用统一措辞就够。已合并的只有自动记账页内部那两层横幅（见批次二）。

**顺带的一个约束**：`FormDropdown` 的 label 就是触发器的占位文案，且 `maxLines: 1` + ellipsis（`form_dropdown.dart:162`、`:476-479`）。带图标的 4 字标签至少要 136dp 才不被截成「账户类…」，所以宽度必须一起改（账户 120→148、预算 132→146）。

#### P1-5 空状态 CTA 是纯图标

**现象**：账户（`:1325-1330`）、预算（`:784-802`）、分期、自动记账的空状态按钮多为 `AppIconActionButton`——**只有图标，靠 tooltip 说明**。首次使用用户看不懂。

**建议**：空状态 CTA 一律带文字（`FilledButton.icon` 或 `TextButton.icon`）。只有「分期」做了三级链式引导（`:305-346`），可作为其他页的模板。

**已处理（批次三）**：七处空态 CTA 全部换成带文字的按钮——账户、预算、自动记账、分期（信用账户 / 支出分类 / 分期计划三级）用 `FilledButton.icon`（次级动作用 `OutlinedButton.icon`）。**页面级常驻的 ＋ 保持纯图标**：它旁边还有排序 / 隐藏金额 / 筛选三个同排按钮，文字按钮会把这行撑爆；而空态不一样——那是新用户唯一能看到的界面，没有 tooltip 就没有任何线索。

#### P1-6 记一笔表单：字段顺序与折叠取舍

**现象**：
- **「名称」排在第 3 位**，早于账户（`:469`）、分类（`:513`）、日期（`:537`）——后三者才是更高频字段。
- **备注被折叠进「更多信息」**（`:572-586`），至少 2 次点击才能输入。

证据：`transaction_form_dialog.dart:383-543`、`_AdvancedTransactionFields:1392-1423`。

**建议**：
- 顺序调整为：金额 → 分类 → 账户 → 日期 → 名称 → 支付方式 → 更多。
- 备注提到顶层（或至少在「名称」旁给一个「备注」快捷展开）。

#### P1-7 转账表单与记一笔表单不一致

| 维度 | 记一笔 | 转账 |
|---|---|---|
| 金额自动聚焦 | `autofocus: !_isEditing` | **无** |
| 「保存并继续」 | 有 | **无** |
| 备注位置 | 折叠在「更多信息」 | **顶层可见** |
| 编辑态日期快捷项 | 隐藏 | **恒显示** |

证据：`transaction_form_dialog.dart:387`、`:611-617`、`:539` vs `transfer_form_dialog.dart:131-139`、`:225-231`、`:215`、`:235-239`。

**建议**：三处对齐——转账补 `autofocus` 与「保存并继续」；备注位置统一（建议都提到顶层）；日期快捷项口径统一为「编辑态也显示」。

**已处理（批次三）**：前两处与第三处的日期口径都做了。

- 转账补 `autofocus: !_isEditing`（与记一笔同一行代码口径）。
- 转账补「保存并继续」：给 `TransferFormDialog` 加了与 `TransactionFormSubmit` 完全同构的 `TransferFormSubmit` 回调。传了 `onSubmit` 时表单自己完成写入（并把失败文案回显在表单上，而不是发个转瞬即逝的 toast），因此能从同一个对话框连记多笔；没传时保持原有的「把结果 pop 给调用方」契约，另外三个调用点（账户页信用卡还款、编辑流水）不受影响。
- 记一笔的日期快捷项由 `!_isEditing` 改为恒显示，与转账一致——改一笔记错日期的流水时，「今天 / 昨天」正是最常用的修正方式。
- **备注位置留到第四批**（P1-6）：它和「表单字段顺序」是同一个决策的两半，要一起定，免得同一张表单改两遍。

### P2 · 查阅效率与打磨

#### P2-1 统计页 22 张卡分 5 页，定位困难

**现象**：22 张卡按 5 组分页（概览/消费/渠道/预算/账户），每页内还要纵向滚动。要找「净值趋势 / 信用使用率 / 未来账单」，需**横滑 4 次 + 页内下滑很久**。且页签只有约 32px 高（`:1478`），细长易误触。

证据：`money_dashboard_layout.dart:14-37`（22 卡）、`:68-84`（5 组）；`money_statistics_section.dart:1387-1431`（Pager）、`:1460-1524`（页签）。

**建议**：把页签做成带图标 + 组内卡片数的分段控件，高度提到 40px；或提供「搜索卡片 / 快捷跳转」。自定义看板 Sheet 里 22 项也是平铺（`money_dashboard_editor_sheet.dart:90-110`），同样建议按组分节。

#### P2-2 账户页分组 chips 不含金额

**现象**：资产 / 信用负债 / 停用 三组用 chips 切换单组显示，chips 上只有名称 + 数量，**没有金额合计**——而这正是用户分组时最想看的信息。

证据：`money_accounts_section.dart:1054-1186`（`_AccountsHeader`）、`:1171-1248`（`_GroupChip`）。

**建议**：chips 上补金额合计（如「资产 · ¥12,340」），或改为可折叠分组堆叠，一屏同时看到三组。

#### P2-3 标签筛选无独立入口；商家搜索入口与文案不符

**现象**：
- 标签筛选只能从统计页下钻带过来，列表内**没有入口**（代码注释自述）。
- 常驻搜索框的 hint 写着「搜索名称、备注、商家」，但实际只传 `keyword`，**商家是另一条 `_merchantFilter`**，只在高级筛选抽屉里。

证据：`money_transactions_section.dart:385-386`（注释）、`:263-278`（hint）、`:951-952`、`:2650-2659`。

**建议**：标签筛选补一个 chips 入口（可复用状态 chips 那一行）；把「商家」从搜索框 hint 里去掉，或让搜索框真正覆盖商家。

#### P2-4 「再来一笔」（复制）只在详情内

**现象**：复制一笔必须先点开详情再点按钮。滑动动作里没有复制。

证据：`transaction_detail_content.dart:588-594`；`transaction_card.dart:71-102`（滑动动作无 duplicate）。

**建议**：滑动动作或 `⋯` 菜单里补「复制」，这对「同一笔常见支出」场景收益很大。

#### P2-5 顶部操作行属于压线布局

**现象**：一个 `Expanded` 分段控件 + 4 个 44px 图标按钮 + 4 个 8px 间距，靠把 `minSegmentWidth` 压到 44 才在 360dp 放下四段。字体放大或更窄屏有溢出风险。

证据：`money_transactions_section.dart:280-331`，注释 `:285-287`。

**建议**：把「导出 / 回收站」收进 `⋯` 菜单，只留「排序 + 高级筛选」在操作行。
