3净资产卡为什么好看

这是全篇最有价值的一条：好看的原因不是「用了紫色」，而是它的色相跨度足够大——而 App 里其它三个渐变都做不到。

第二个原因：它是全局唯一的紫色

整套色板用到的色相只有 6°（珊瑚）、24~33°（暖中性 / 信用 / 警示）、155~167°（收入 / 辅色）、220°（转账）、242°（焦点）、333~345°（三色 / 支出）。 紫色的 270~280° 区间是空白，净资产卡一出现就自然抢走注意力。

4四个需要处理的问题

按影响程度排序

1
浅色主题的金额色全部达不到 WCAG AA

金额是 14px 粗体，不适用「大字号 3:1」豁免，需要 4.5:1。实测：收入 4.36、支出 4.13、转账 3.99、信用 4.21、警示 2.68。深色主题则全部优秀（8.4~10.8:1）。

credit#8757BE4.21:14.00:14%
warning#856C062.68:12.55:125%
2
六个语义色被要求同时干两件事

同一个 warning 既当警示条的背景填充，又当「已超支」的文字颜色。填充色只需要 3:1（非文字组件标准），文字色需要 4.5:1 —— 一个值不可能同时满足。现在是填充够鲜亮、文字就不够暗。

3
净资产卡的颜色是硬编码的，不在主题系统里

money_accounts_section.dart:750 直接写了 Color(0xFF3E4A8C) 和 Color(0xFF4F5FB0)，再用 Color.lerp 和 primary / secondary 混合。这套你认可的配色目前无法复用到别处，也不受主题管理。

4
深色主题下，净资产卡右端的文字几乎看不清

渐变右端 #4A7D85 上的白字只有 2.36:1，而「负债」数值用的琥珀 #FFD9A0 更低到 1.76:1。浅色主题的右端 3.85:1 也偏弱。

5建议

按「改动大小 / 收益」排序，前两条几乎无风险

A. 把渐变提成主题 token（推荐先做）

新增一个 AppHeroGradients 主题扩展，和 AppMoneyColors 并列。每个渐变定义 三档停靠点（现状就是三档）：

C. 更彻底：拆成 fill / text 两个 token

AppMoneyColors 从 6 个字段扩到 12 个：

// 填充：保持鲜亮，门槛 3:1
warningFill = #E08A1E
// 文字：压暗，门槛 4.5:1
warningText = #937008
// 其余五个同理

代价是调用点要选对 token；好处是警示条保持醒目，文字也不会糊。

D. 顺手处理一个死配置

themeSeedColor 在 user_preferences 表里有列、有读写方法、注册时还写了默认值，但 app_theme.dart 里一次都没有读它——主题用的是写死的 AppThemeTokens。 要么把它接回主题（真的支持换主题色），要么删列。留着是最糟的选择：下一个人会以为它能用。

6一句话小结

整套配色的暖中性部分做得很好——三个色相挤在 4° 内、只靠明度分层，这是它「暖」且耐看的根基；深色主题的语义色也全部达标（8.4~10.8:1），比大多数 App 都干净。

问题集中在两处：浅色主题的语义色全部差一点点（2~7% 的压暗就能过线，只有 warning 差 25%），以及语义色与品牌色、暖中性之间有 5 组撞色（夹角 4°~12°）。

而你喜欢的净资产卡，本质上是这套色板里唯一一个跨越了 90° 色相的渐变，也是唯一用了紫色的地方。把这个「大跨度 + 冷色区」的做法提成 token 复用到首页 Hero，是最省力的一步升级。
