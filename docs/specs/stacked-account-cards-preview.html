设计决策

为什么不能简单把 ListView 换成 Stack

核心冲突 现有列表挂了三个交互，堆叠会直接撞车：
左滑 AppSwipeActionTile 编辑/删除 —— 被埋在后面的卡只剩一条缝，够不着；
拖拽 长按排序 —— 藏在后面的卡抓不到把手；
分页 PagedLoadMoreList —— 堆叠是固定高度 Stack，天然不可滚动。
结论：堆叠与「每张卡都能被完整触碰」互斥，必须拆成两个状态。
双态切换 浏览态（默认）＝堆叠，负责看；管理态＝现有列表，负责改。
管理态复用既有「管理与排序」入口，不新增 UI，实现完全保持现在的 PagedLoadMoreList + _AccountTile。
几何取舍 三种几何各有代价，推荐几何 2：
几何 1（向下偏移）：顺序自然，但露出的是卡片下半部分 → 只见余额、不见名称，会出现「孤立数字」。
几何 2（裁顶 + 8px 叠压）：顺序自然 且 露出图标+名称 → 身份能认出，叠压唇边保留卡组质感。代价：后续卡要额外套一层 ClipRect。
几何 3（向上偏移）：露出顶部，但最上方是最后一张卡，顺序与列表相反，阅读预期错乱。
52px 裁切高度 不是随手取值：52 = padding 12 + 图标 38 + 2，正好切在图标行结束、10px 间距开始处。
再少图标被切一半，再多就退化成普通列表。这个数与卡高(108)/内边距(12)/图标(38)绑死， 落地时抽成常量 stackPeekHeight。
层次表达 仅首卡投影 0 10px 26px；往下 opacity 递减 0.97 → 0.88，zIndex 递减。 越深越轻，形成「一叠卡」的质感。
张数上限 只堆前 6 张，超出折叠为「还有 N 张」→ 进管理态。 堆叠是固定高度，20 张堆出来比列表还长，失去意义。
边界情况 0 张 → _EmptyAccountsPanel；1 张 → 不堆叠，直接单卡；>6 张 → 折叠提示。
暗色主题 待验证 层次感靠阴影，暗色下阴影几乎不可见， 需改用「边框 + 明度差」补层次。实现时必须单独调。
卡片本体 零改动 _AccountTileContent 已是 AccountCardBackground + 3 行内容，堆叠只改外层容器排布，不动卡内结构。
值不值得做 它是浏览体验升级，不是信息密度升级（几何 2 下余额信息其实被藏了）。
真实收益：一屏看完所有账户（590 → 284）+ 钱包质感。
代价：多一个状态要维护、两套布局分别测。
建议先只做浏览态堆叠，管理态保留现有列表（本来就是两个入口），看反馈再决定是否合并。
