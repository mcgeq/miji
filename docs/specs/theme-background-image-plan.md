# 背景图主题改造方案

素材来源：`scriptures/IMG_*.JPG`（7 张）。目标是把现行主题改成「以这类水彩插画为底」，
并同步调整文字 / 强调色。

本文只做**分析 + 方案**，未改任何代码。

## 二、三个量化结论（决定方案边界）

以下数字由 Pillow 逐行采样 + WCAG 相对亮度算出（脚本见文末「复现方法」）。

### 结论 1：文字**不可能**直接放在图片上 —— 这是数学上的不可能，不是调色能救的

现行次要文字 `#615D58` 的相对亮度 L = **0.1223**。
要让它在任意背景像素上达到 AA 的 4.5:1：

```
(L_bg + 0.05) / (0.1223 + 0.05) ≥ 4.5   →   L_bg ≥ 0.725
```

L = 0.725 对应 sRGB 约 **`#DDDDDD`**。

而这几张图插画区的实际亮度是 **0.05 ~ 0.25**（最暗像素 `#254635` / `#476072` / `#3581A2`），
差了一个数量级。实测次要文字压在最暗像素上的对比度只有 **1.01 ~ 2.19**。

> 换句话说：想安全地「在图上放字」，必须先把图处理成近乎纯色的极淡水彩 ——
> 那时它已经不是插画了。**任何靠遮罩 / 调文字颜色来救的路，都会把图救没。**

推论（架构原则）：

> **文字永远落在「不透明 ≥0.85 的面」上；图片只出现在面之外。**

这条应该做成测试不变量，而不是靠自觉。

### 结论 2：「沉浸式大图 + 白字」在这批素材上不成立

这几张图**太亮**（顶部平均色亮度 0.51~0.79，最亮处 `#E1EBED`~`#FEF9E5`）。
白字压上去只有 **1.06 ~ 1.27:1**。叠黑色遮罩后：

| 黑遮罩 | 0 | 0.15 | 0.25 | 0.35 | 0.45 |
|---|---|---|---|---|---|
| 白字对比度 | 1.06~1.27 | 1.49~1.78 | 1.93~2.30 | 2.56~3.02 | 3.50~4.09 |

即使遮罩到 0.45（图已经黑掉一半），白字仍**到不了 4.5**。
想上白字 Hero，得另找深色素材；这批不行。

### 结论 3：毛玻璃卡片有硬上限 —— 不透明度 ≥ 0.85

卡片（`surface #FBF6F0`）以 alpha 压在图片最暗像素上时，次要文字对比度：

| 卡片不透明度 | 0.70 | 0.75 | 0.80 | **0.85** | 0.90 |
|---|---|---|---|---|---|
| IMG_4567 | 4.22 | 4.50 | 4.79 | 5.07 | 5.39 |
| IMG_4568 | 4.62 | 4.86 | 5.10 | 5.32 | 5.58 |
| IMG_4569 | 3.91 | 4.22 | 4.57 | 4.94 | 5.29 |
| IMG_4570 | 3.56 | 3.93 | 4.31 | **4.73** | 5.13 |

最难的 IMG_4570 需要 **0.85**。也就是说：图片透过卡片的可见度最多 **15%** ——
「玻璃感」在视觉上几乎看不出来。**别为这点收益付性能代价**（`BackdropFilter` 是
每帧 GPU 模糊，列表滚动时最贵）。

## 三、最容易漏掉的一条：色系冲突

| | 色相 | 说明 |
|---|---|---|
| 现行主题「暖纸 · 靛蓝」 | 中性层 **72°**（暖）+ 强调色 `#4269D3`（靛蓝） | `app_theme_tokens.dart` |
| IMG_4567 / 4568 / 4569 | **184° ~ 210°**（冷青蓝） | 与现行暖中性层**近互补** |
| IMG_4570 | **48° ~ 58°**（暖米黄） | 与现行暖纸**同族**，兼容 |

实测现行靛蓝 `#4269D3` 在三张冷蓝图上的对比度只有 **1.64 ~ 4.12**，大片区域低于 3:1 ——
**蓝底蓝字**。

所以「上冷蓝背景」不是换个背景图就完了，它**连带要求**：
中性层从暖转冷、强调色必须换（不能继续用靛蓝）。这是主题级改动。

反之，**IMG_4570 是唯一与现行主题同族的**，只想加背景、不想动色系时它是更省的选择 ——
但它和另外三张不是一个风格，不能混。

## 四、四个方案

### 方案 A：极淡水印底（推荐先做）

整张图以 **alpha ≤ 0.10** 压在现行 `background #F2EDE6` 之下，卡片**全部保持实色**。

| alpha | 0.06 | **0.10** | 0.16 | 0.25 |
|---|---|---|---|---|
| 次要文字（最暗处） | 4.76~5.35 | **4.76~5.00** | 3.96~4.68 ⚠ | 3.65~4.54 ✗ |

（现行纯色底是 5.61，作为参照）

- **改动**：新增一个 `AppBackdrop` 组件 + `pubspec` 加 assets，**不动任何 token、不动任何页面**
- **风险**：极低。alpha 0.10 时最坏值 4.76，仍有 0.26 余量
- **收益**：打破纯色单调，水彩纹理若隐若现

### 方案 B：分层背景（A 的加强版，同一套基建）

顶部 / 头部区域露出较完整的图（alpha 0.35~0.5，且该区**只放正文色或深底白字块**），
列表区回落到 A 的强度。图片用 `BoxFit.cover` + `alignment.topCenter`，
把装饰集中的底部留在屏幕外或可视区下沿。

- **前提**：IMG_4569 顶部本身偏暗（`#ACC1CF`），只适合 4567 / 4568
- **改动**：在 A 的基础上加一个「强背景区」组件，用在 3~5 个页面头部

### 方案 C：毛玻璃卡片

按结论 3，卡片不透明度必须 ≥0.85，视觉收益 ≈ 无，还要付 `BackdropFilter` 的性能代价。

**建议不做。**

### 方案 D：换冷雾蓝主题（真正的「重构主题」）

如果要的正是「整 App 变成海盐蓝那套」，那么工作量和 A/B 不是一个量级：

| 层 | 现行 | 目标方向 |
|---|---|---|
| 中性层 | 暖 72°、彩度 0.010、四级明度 | 冷 **~200°**、彩度 0.010、四级明度重新排 |
| 强调色 | `#4269D3` 靛蓝 | 换色相（靛蓝在冷蓝底上不成立），需重新求解文字版 / 填充版 |
| 语义层 | 五色（色觉缺陷梯度已求解） | **色相可不动，但每色对新的冷中性面要重算 ≥4.5** |
| Hero 渐变 | 紫→青 / 暖赭金 / 品红 | 暖赭金在冷底上会重新「突兀」（D2 文档里正是因为暖底才选赭金） |
| 图表色板 | 8 色（≥3:1 已求解） | 同样要重算 |

**色值必须按 WCAG 对比度 / APCA / OKLab ΔE / 色觉缺陷模拟 核过**。**不要手搓色值** ——
手搓会破坏「语义色在三种色盲下 ΔE ≥0.06」这类不变量。（本项目原来有一套求解 + 校验脚本，
随主题定稿已移除；走没有工具的路径时，这些指标要自己算。）

工作量参考 D2 那次：4 个主题文件 + 7 个消费方文件 + 测试，且当时 `flutter test`
548 passed / 12 failed 需保持不新增失败。

## 五、推荐路径

**先 A，再 B，D 单独另议。**

A 和 B 共用同一套基础设施（背景层组件 + 强度参数），一次实现、一个开关切换，
可以先上 A 看效果，不满意再调强度，不用改两遍。

D 要看你是不是真的想换色系 —— 那是另一个决策，不该和「加个背景」绑在一起做。

## 六、落地清单（方案 A / B）

1. **`pubspec.yaml`** —— `assets:` 段目前**整段是注释掉的**，项目零图片资源。
   新增：
   ```yaml
   flutter:
     assets:
       - assets/backgrounds/
   ```
   只打一张（~200KB，JPEG）。图本身就是模糊底纹，**不需要 2x/3x**；
   941px 宽在 1080 宽屏上 `cover` 放大 1.15 倍，可接受。

2. **新增 `lib/core/presentation/components/app_backdrop.dart`**
   `DecorationImage` + `BoxFit.cover` + `alignment` + 白色 scrim 叠层 + `opacity`。
   **不要**用 `BackdropFilter`。

3. **`main.dart` 一处挂载** —— 项目有 **67 处 `Scaffold(`**（14 个页面文件），
   逐页改不现实。在 `MaterialApp.router` 的 `builder` 里包一层即可全局生效：
   ```dart
   builder: (context, child) =>
       FToastBuilder()(context, AppBackdrop(child: child)),
   ```
   这是本方案最省的关键：**零页面改动**。

4. **深色模式** —— 这四张都是浅底图，深色下不能直接用。
   深色模式把 alpha 降到 **0.04~0.06** 并叠深色 scrim，或直接关闭背景。
   由 `AppBackdrop` 读 `Theme.of(context).brightness` 自行切换。

5. **测试不变量**（放 `test/core/theme/`）
   - 背景层 alpha 浅色 ≤0.10、深色 ≤0.06
   - `AppSurface` 的背景色 alpha ≥0.85（守住结论 1 的原则）
   - 现行 6 类不变量（`test/core/theme/*`）不得回退

6. **可选：背景开关** —— 现行偏好只有 `AppThemeModePreference`（light/dark/system），
   没有皮肤概念。若要让用户选底图，需扩展 `user_preferences_entity.dart` +
   `drift_preferences_repository` + 设置页。**建议先不做**。

## 七、两个必须处理的问题

### 版权

IMG_4564 / 4565 / 4566 带「公众号：记钱钱App」水印，是**别家 App 的宣传图** ——
只能当 mood board，**不能进包**。4567~4570 未见水印，但与前者同源，
来源与授权不明，**直接商用有风险**。

建议：用 ImageGen 按同样风格（水彩海洋、装饰在底部、中部留白）自己生成一批，
顺便解决下面两个问题。

### 分辨率与裁切

941×1672 / 720×1280 都不是标准壁纸尺寸，且手机屏比例已是 19.5:9 ~ 20:9，
`cover` 必然裁掉上下。装饰在底部 → 会被裁掉一部分。
自生成时直接按 **1170×2532** 出图、装饰放在**底部 15% 与四角**，可规避。
