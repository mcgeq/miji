今日视图 · 重设计稿

现在的「今日」（today_action_list_view.dart）是一张只有两档分组的平铺清单： 「逾期 / 待完成 / 已完成」三个小节，行里塞着一枚零信息量的「任务」标签，顶部只有一行小字计数。 它回答不了「今天还剩几件」「最紧的是哪件」「先做哪个」，也加不了任务。 这一稿把它重做成一屏「今天该怎么过」：顶部 HUD 给结论、中间按时间分段、行内可直接完成、顶部常驻添加。

一、现状诊断：十个具体问题

功能缺陷
  • 今日页根本加不了任务。gtd_page.dart 里 _GtdPanel.today 的工具栏只有一枚「新建计划」（push('/app/gtd/plans/create')）；「新建任务」只挂在 _GtdPanel.tasks 上。想往今天加一件事，得先切到「任务」页——这是当下最硬的一处不便。
  • 没有时间轴。排序是「逾期 → 优先级 → sortTime」，dueAt 只在行尾以 18:00 小字出现。一天里什么时候做什么，布局上完全看不出来。
  • 分组等于没分。「待完成」承载 90% 的行，标题只提供计数，不提供组织作用。
  • 没有批量操作。逾期攒了 8 条，只能一条条点；也没有「把逾期全部改到今天」这类一键处理。
  • 没有视图控制。不能切换排序（时间 / 优先级 / 清单），不能只看任务或只看打卡。
布局与视觉
  • 行内杂音。每行挂一枚「任务」pill（tertiaryContainer），整页都是任务，这枚标签零信息量；而真正该显示的分类 / 清单、来源反而不显示。
  • 两类行不同构。待办行是「圈 + 标题 + meta」，打卡行直接复用 HabitPlanRow（图标 + 名称 + 副行 + 环形/计时/拍照）。第二行格式、右侧控件、基线都对不齐。
  • 完成态视觉太弱。只有标题加删除线 + 变灰，行高不压缩、meta 行照常显示，已完成区仍占满屏。
  • 已完成区默认展开，还会被强制展开。didUpdateWidget 里 completed.length 一变多就 _expanded = true：勾完一条，整块内容顶下来，列表跳动。
  • 命中区太小。勾选圈 22px，GestureDetector 嵌套在整行 InkWell 内，容易误触进详情；且没有滑动手势——移动端「完成 / 更多」的通用语言缺失。
  • 空态没有出口。只有一句「创建任务或打卡计划，开始行动吧」，没有任何按钮。

三、五条设计原则

「今日」不是「全部任务」的一个筛选结果，它是一个有开始和结束的一天。 所以它必须回答：还剩几件、最紧的是哪件、什么时候做、做完能看到什么。
  • ① 先给结论，再给清单。顶部 HUD 一屏内回答「还剩几件 / 最紧的是什么」，列表只负责执行。
  • ② 时间是唯一主轴。有 dueAt 的按 上午 / 下午 / 晚上 归组；没有的进「随时」，且「随时」紧随逾期（先清掉无约束的杂事，再进入有时间约束的日程）。打卡单独成段（动作控件不同）。
  • ③ 一类行骨架，两种右侧控件。左槽 26px、中槽「标题 + 一行 meta」、右槽动作 —— 待办与打卡共用，只有右槽不同（勾选圈 / 环形 / 计时 / 拍照）。
  • ④ 完成是行内一等公民。点圈、右滑都能完成；完成后原地降饱和，收进「已完成」折叠区（不再强制展开）。
  • ⑤ 今日页必须能加任务。顶部常驻输入行，一键落到今天。

变在哪儿
  • HUD 取代小字计数。环内是「还剩下的件数」（不是完成数——用户看今日是要知道还要做多少），右侧一句「最紧」直接指出第一条该做的事。
  • 删掉「任务」pill，换成分类色点。整页都是任务，标「任务」等于没说；标「工作 / 生活 / 健康」才有筛选价值。
  • 时间分段替代「待完成」。「上午 / 下午 / 晚上 / 随时」四段；没有 dueAt 的落「随时」，不再和定时任务混在一起。
  • 打卡单独成段。它的完成方式（计数 / 计时 / 拍照）与勾选不同，混排会破坏「右槽 = 完成」的一致性。
  • 已完成默认折叠且只显示一行。不再强制展开，勾完不跳动。
  • 分组标题带批量入口。「逾期」右侧直接给「全部改到今天」——比长按多选轻，且就长在最需要它的地方。

屏 2 · 手势与批量：右滑完成 / 左滑改期删除（To Do、滴答的通用语言）； 长按进多选，底部批量条给「完成 / 改到今天 / 更多」。批量操作不再只能一条条点。
交互规格
  • 右滑完成：阈值 25% 行宽，越过后松手即完成；完成后行原地降饱和 400ms，再收进「已完成」（Things 3 的节奏，避免列表瞬间重排）。
  • 左滑更多：露出「改期 / 删除」，不再往行内塞 ⋯ 按钮。
  • 点圈完成：保留，但命中区从 22px 扩到 44×44（用 padding 撑，视觉仍是 24px 圈）。这是当前最容易误触进详情的地方。
  • 长按多选：底部浮出批量条；「改到今天」专治逾期堆积。
  • 打卡行不参与多选：它是计数/计时语义，「完成」与「撤销一次」不同；多选只作用于待办。
一处刻意不做
  • 不做拖放排序。今日视图是「一天的执行清单」，不是「规划板」；拖动在 6 英寸屏上的命中率远低于滑动手势，而收益（手动排优先级）已被「时间分段 + 逾期置顶」覆盖了。
  • 不做小时块时间轴。Structured 那套超过 8 件事就崩，且与「随时」类任务天然冲突。

八、已确认的四个决策

2026-10-20 拍板
议题结论
打卡的归属单独成段（不并入时间分段）。右槽控件在一段里换三种形态会破坏「右槽 = 完成」的一致性。
HUD 环内剩余件数（6）。今日视图要回答的是「还要做多少」，不是「做了百分之多少」。
「随时」段位置紧跟逾期，排在上午 / 下午 / 晚上之前。先清掉无约束的杂事，再进有时间约束的日程。
「从待安排挑」做。复用既有的 allTodoTasksProvider 在内存里筛（无 scheduledDate、无 dueAt、无 occurrenceDate），不新增 repository 方法。
实现拆解
① todo/domain/today_board.dart：新增纯函数 buildTodayBoard（分段归组 + 剩余件数 + 最紧提示）。
② todo/application/today_board_providers.dart：todayBoardProvider + todayCompletedTodoProvider（今天完成的待办，让「已完成」段不再只有打卡）+ todayUnscheduledProvider（待安排）。
③ today_action_list_view.dart 整体重写。
④ gtd_page.dart 的 _GtdPanel.today 补一枚「新建任务」按钮。
数据层不动：TodayActionView 保留原样（首页多处依赖），分段只是它之上的派生层。
