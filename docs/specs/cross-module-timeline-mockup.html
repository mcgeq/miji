屏幕 3 · 未解锁 / 空态：经期整行遮蔽（连标题都不给）、金额走全局隐私开关；空态不伪造事件。
为什么这样分组
事实与承诺必须分开摆
  • 「待发生 / 已发生」两区：混在一起时，用户会把「计划今晚 22:00 决定买不买」当成已经发生的事。
  • 已发生默认折成一行，点开才展开 —— 不折会让「今天还剩什么」被历史淹没。
  • 逾期类（承诺未完成）右侧用红点而不是红字：红色只标「需要你处理」，不标「过去」。
四类时间，三种形态
不靠颜色，靠轮廓
  • 事实：实心图标、竖条实线。
  • 承诺：描边图标 + 「承诺 / 计划」小标签。
  • 推断：虚线竖条 + 「预测」标签 + 整体 72% 不透明。
  • 容器（预算周期、经期）：不进行列表，画成顶部淡色区间带。
  • 灰度打印下这三者也能分辨 —— 颜色只用来标模块。

时薪
「今天 09:30 要体检、25 日要还房贷、今晚 22:00 那副耳机冷却结束、这周是经期」——这句话现在要跨四个模块才拼得出来。时间线只做一件事：把这句话一次说完。
不做的事
  • 时间线只读：没有左滑、没有长按、没有在这里新建。加待办去「打卡」，记一笔去「记账」。
  • 不做无限历史滚动：回顾按月分页就够。
  • 不经二次验证不显示经期与金额 —— 时间线要登记进敏感路由。
  • 不做跨模块因果（「经期导致多花钱」这类结论），只在回顾里给并列统计。

静态稿：没有交互，只表达布局、层级与状态。
