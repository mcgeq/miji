二、为什么重做：现有体系的问题

功能层面的硬伤

  • 四级表面只差 4% 明度。浅色下 #FBF6F0 / #F6F1EB / #F2EDE6 / #ECE7E1 相邻两级的亮度差不足 0.02， 去掉描边和阴影后卡片层级几乎消失——而这个 App 的列表、卡片、输入框全靠这一层。
  • 主色有两套。primary #4269D3 与 primaryFill #5E88F6 并存， 填充版配近黑前景 #03001F。深色模式下填充版又变成浅蓝 #CADBFF 配深蓝字—— 同一组 token 在两套模式下语义相反，接手的人只能靠猜。
  • 没有语义容器层。tag / chip 只能用 withValues(alpha: .12) 硬凑底， 深色模式下透明度叠在深色面上会发灰，全库有 360 处这种写法。
  • Warning 是暗橄榄 #473D00，明度 L*≈25，单独当图标/文字用时几乎就是块黑。
  • 健康模块另起炉灶。health_theme.dart 里 7 个阶段色硬编码、按 brightness 分支， 不受主题 token 管，换个主题它不跟着变。

竞品在做什么

  • 深色必须重做，不能反转。2026 年 fintech 的共识：把浅色反过来看会得到一坨浑浊的灰面。 现有深色确实是独立定的，但中性层仍是「浅色减光」，层级关系没重排。
  • 功能色跨品牌几乎一致。收入绿 / 支出红 / 警告琥珀 / 信息蓝在 Copilot、Monarch、YNAB、Wealthsimple 里基本同色——差异只在中性面与主色。这也是本稿让语义色三套共用的依据。
  • 主色窗口很窄。绿给了收入、红给了支出、琥珀给了警告、紫给了信用、青给了转账。 主色只剩「蓝 240–270」和「赭 40–55」两个空档——本稿三个方向正好各占其一。
  • 暖中性面 + 冷主色仍是国内主流（微信读书、鲨鱼记账）； 近无彩中性 + 单一强调是 Copilot / Notion 一派，画面让给用户数据（分类色）。

三、颜色的功能分配（这次重排的核心）

米记的画面里有两类颜色：系统的（语义、图表、品牌）和用户的（193 个分类自带的颜色）。 分类色是画面里最花的东西，所以中性面刻意压到近乎无彩——谁该跳出来，是设计出来的，不是碰巧。

色相归谁为什么是这个位置
27–31°支出 / 超支红。中国记账语境下支出=红是铁律（与股市红涨绿跌无关，两套场景别混）。
85–88°警告 / 逾期琥珀。与红拉开 55° 以上，色盲模拟下仍可分辨（本稿 ΔE 0.097）。
147–149°收入绿。与琥珀、与青都隔着 60° 以上。
178–189°GTD 专注青绿。只出现在「今日 / 习惯」屏，与转账不在同一屏，故容忍较小色相差。
213–217°转账蓝青。转账是「钱的位置变了，总数没变」，用中间色而非冷暖色是刻意的。
250 / 45 / 268°品牌主色（A/B/C）剩下唯一的两个空档：蓝、赭。
312–325°信用卡紫。与红色系、蓝色系都拉得开。

冗余编码：色相在色盲眼里会被压到一起，所以五个语义色还叠了一层明度梯度 （浅色 L 0.44→0.49，深色 L 0.70→0.83）。去色视图下靠这层梯度仍能分出「收入/支出/转账」。

四、三个方向怎么选

方向性格代价 / 已知取舍
A 砚青
冷灰石面 + 钢蓝		 专业、安静、数据优先。中性面几乎无彩，分类色和金额数字是画面主角。最接近 Copilot / Notion 一派。 最安全，但也最没有「记忆点」——三个方向里最不像一个独立产品。
B 陶土
暖砂纸面 + 赭陶		 手账气、温度感，长时间阅读最不刺眼。延续了现有体系的「暖」，但暖得更有依据。 主色占了红橙区，导致超支卡只能靠明度和彩度与品牌卡拉开（ΔE 0.074，是三者里最紧的一对）。
C 夜屿
近黑中性 + 蓝紫		 深色优先，中性层压得最深（背景 #0E0F13），高彩度主色。科技感与高端感最强，暗光下最舒服。 浅色模式下与 A 差异不大——它的价值主要在深色。若用户以浅色为主，等于白做。

五、落地要动的地方

  • lib/core/theme/app_theme_tokens.dart — 换成新色值；浅色/深色各自独立的 token 命名保持对称（现在深色部分缺 primaryFill 对称定义）。
  • app_design_tokens.dart — AppMoneyColors 增加 *Container 六色；AppHeroGradients 保留但改用新求解值。
  • app_theme.dart — 深色模式的语义色现在内联写在 build 里，浅色却读 AppThemeFallbacks，两处口径必须合并。
  • features/health/presentation/health_theme.dart — 7 个阶段色建议收进主题扩展，或至少与主色系对齐色相节奏。
  • 360 处 withValues(alpha:) 与 105 处硬编码 Color(0x…) — 有了容器层之后可以逐个替换，不必一次做完。

求解与校验脚本：OKLCH→sRGB（越界二分降彩度）、WCAG 对比度、Viénot 三型色盲模拟 + OKLab ΔE。 语义色是带审美惩罚项的随机搜索解出来的（纯最大化 ΔE 会把颜色推到极暗极艳，看着脏）； 图表 8 色是在 5040 种环形排列里挑的，且深浅两模式共用同一顺序，保证同一个分类在两套模式下是同一个颜色索引。
