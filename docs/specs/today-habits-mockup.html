今日 · 习惯打卡 · 界面稿

现在的「今日」里，习惯行整块只能点进详情页 —— 要打卡得离开这一屏； 完成与否只靠行尾一条 4×40px 的细进度条区分；图标还是 22px 的原始 emoji。 这一稿把「完成」做成行内的一等公民：右侧一枚控件，既是进度也是按钮。 取色沿用默认配色「靛墨」，计划颜色只作为图标底色与环形的强调色。

先说清楚现状的六个问题

  • 没有完成入口：_HabitActionTile 的 onTap 是 push('/app/gtd/plans/:id')，整行只能进详情。打卡得去「习惯」tab 或首页卡片。
  • 完成态没有视觉：isCompleted 只是让那条 4px 进度条消失。行不变灰、不打勾、不划线 —— 和未完成几乎一样。
  • 进度几乎看不见：40×4px 的条 + 「3 / 8 杯」小字，「还差多少」要读数字。
  • 图标用了裸 emoji：Text(plan.icon, fontSize: 22)，没走统一的 CheckinPlanIcon；旧默认图钉会原样出现。
  • 触发方式被吞掉：计时、拍照型计划在今日行里和普通点击型长得一模一样，点进去才知道。
  • 同一屏两种完成语言：任务行左侧有勾选圈，习惯行右侧只有细条；行高与基线也对不齐。

屏 3 · 控件状态：四种环、三种计时/拍照、两种勾选。 环内数字是「今天的进度」，目标为 1 时环内直接是勾（不显示 0/1）。
核心决定
右侧那枚控件 = 进度 + 按钮
  • 原来进度是行尾 40×4 的条，完成要进详情页。现在合成一个控件：环代表今天完成到哪，点它就是打卡。
  • 为什么不是「左边圆圈 + 右边进度条」两件东西：一块屏幕上两列控件会让人先找按钮再找进度，而这两件事本来是一件事。
  • 目标为 1 的计划（洗澡、吃药）环内不放「0/1」，直接是勾 —— 一个数字表示「0 或 1」没有意义。
  • 多段计划环内就是数字（3 杯、24 分钟）；目标是 30 分钟时显示分钟而不用百分比，省一次换算。
交互规则
操作结果
点右侧环今天是 +1 段（一次型计划即完成）；满目标自动进「已完成」
点行内其余区域进计划详情（看记录、改计划）
长按行小菜单：撤销一次打卡 / 今天全部完成 / 查看记录
点计时胶囊开始计时 → 再点暂停；长按结束并落一条记录
点拍照胶囊进拍照打卡页
点已完成行的环展开确认：撤销今天这次打卡（不静默改数）
与任务行的统一
  • 两者都是「左侧图标 + 中间两行 + 右侧操作」，行高、字号、间距一致；差异只在右侧控件的形状（圆环 / 圆圈）。
  • 完成语言分开：一次性任务用打勾 + 删除线（这件事结束了）；习惯用绿环 + 降饱和（今天结束了，明天还要做）—— 习惯不打删除线，否则像被取消。
  • 「习惯」那个小标签删掉：图标 + 环已经说明一切，标签只是噪声。
副行放什么
  • 连续天数（🔥 12 天）：习惯的动力来源，比「3/8 杯」更值得被看见，所以放最前。
  • 目标（8 杯 / 30 分钟）：环里只有进度，具体目标写在副行，两者互补。
  • 计时状态（计时中 12:35）：运行中的数字会自己跳动，是全屏唯一需要实时更新的地方。
「打开今日 → 看到喝水 3/8 → 点一下变 4/8」应该在同一屏、同一根手指内完成。之前要先进详情页，那一步就是用户放弃打卡的地方。
落地时与稿子的两处偏差
  • 「已完成」默认展开。稿子里是折叠的，但实现时发现：点完进度环整行立刻折进 「已完成」，屏幕上没有任何东西证明刚才那一下生效了。现在默认展开， 用户手动折叠后的选择在这一屏里保留；新完成一条时会再次自动展开。
  • 完成提示带「撤销」。稿子里撤销只在长按菜单里。达标那一刻弹出的提示条 多了一个「撤销」按钮 —— 点错的那一下应该能当场退回，而不是去猜长按。
没做的（这一轮）
  • 不做「一键全部完成」的批量按钮：习惯的目标各不相同，批量完成是最容易把数据弄脏的操作。
  • 不做拖拽排序：今日的顺序由「逾期 → 待完成 → 已完成」决定，用户不该在这里重排。
  • 不做打卡动画之外的庆祝：环填满有 180ms 过渡，没有彩带、没有「太棒了」。

静态稿：没有交互，只表达布局、状态与操作位置。
