米记主题重做 v2 · 评审稿

v1 被否的原因是「不好看」——中性面压得太灰、主色太闷。这一版从竞品反推： 钱迹 #048CFC 的鲜亮蓝、木木记账的橙色羽毛、iCost 的白底极简， 共同点是「干净底 + 白卡 + 一个敢用的品牌色」，而不是高级灰。

三个方向依然是「中性面 + 主色」不同，语义色与图表色三套共用（换主题不该重新学一遍颜色含义）。 所有数字现场算：对比度走 WCAG 2.1，可分辨性走色觉缺陷模拟 + OKLab ΔE。

二、三个方向

方向对标的竞品性格与代价
A 晴空 Azure钱迹 #048CFC
B 暖阳 Sunny木木记账的橙羽
C 青竹 MintiCost / 随手记的清新

三个方向里，主色与语义色的最近距离分别是 A 0.029（蓝↔转账青）、B 0.016（橙↔警告琥珀）、C 0.021（青↔收入绿）。 这是方案固有代价——5 个语义色几乎占满色环，主色放哪都会挨着某一个，竞品的橙/绿主色同样如此。 解法是场景隔离：主色只出现在按钮/导航/图标，语义色只出现在金额/tag，二者从不并置需要判别。

三、token 与实时校验

下面每个色块右侧的数字是现场算的对比度：绿 = 达标，红 = 未达标。 小号文字按 4.5:1，大号粗体金额按 3:1。

四、与现有体系的差异

  • 主色拆成三个明确角色：primary（文字/图标，on 表面 ≥4.5）、 primarySolid（按钮/FAB 底）、primaryContainer（chip 浅底）。 现有体系里 primary #4269D3 与 primaryFill #5E88F6 并存、 深色下又反过来，属于两套语义打架。
  • onPrimarySolid 由 token 给，代码不要写死白/黑：浅色是深字（亮橙按钮配深棕字）， 深色同。写死白色在 B 方案上会得到 3.4:1。
  • 新增语义容器层 *Container：现有体系没有这一层， tag/chip 只能用 withValues(alpha:.12) 硬凑，全库 360 处，深色下叠在深面上会发灰。
  • 语义色两套（vivid + strong）：大号金额用 vivid，小号文字用 strong。
  • 浅色下 surface 与 raised 同色，层级交给阴影与描边—— 这正是 v1「四级只差 4% 明度看不出层级」的正解。
