# 跨模块时间线：分析与方案

> 2026-10。仅设计与分析，不含代码。
> 问题：待办、计划（习惯打卡）、记账、经期各自有时间，但没有一条共用的时间轴；
> 用户想知道「这周我要面对什么」「上个月发生了什么」，只能一个模块一个模块点。

---

## 一、现状盘点：已经有什么

| 模块 | 已有的时间相关界面 | 时间数据 |
|---|---|---|
| 待办 | 今日面板、月历、按日期筛 | `scheduledDate`（日）、`dueAt`（时刻）、`completedAt`（事实）、重复规则 + 实例 |
| 计划/打卡 | 今日面板、同一个月历、打卡记录 | 频率（日/周/月/cron/一次）、提醒、`recordDate`（日）+ `completedAt`（时刻） |
| 记账 | 流水列表、统计、**未来现金流卡**、预算周期 | 流水 `transactionAt`（时刻）、分期期次 `dueDate`、自动记账模板（周期展开）、账单提醒 `dueDate`、预算周期区间 |
| 经期 | 首页周期卡、**未来 7 天预测**、日历标记 | 记录 `startDate..endDate`（日）、**预测**（下次经期 / 易孕窗 / PMS） |
| 时薪 | 薪资历史（按月）、年度账、想买清单冷却 | 段起点（月）、年终奖（年度）、加班（日）、冷却截止（时刻） |

**已经连起来的地方**（重要，说明方向可行）：

1. `gtd_page.dart` 的月历：把**待办 + 打卡**合并到同一天，点日期看当天两边的明细。
2. 首页：`board.money / board.health / board.action` 三块「今日」，加上
   `homeCrossInsightProvider`（记账 + 待办 + 健康的洞察合并，按严重程度排序，
   每条带「看待办 / 看健康」的跳转目标）。这是**跨模块只读聚合**的既有先例。
3. 记账内部：`upcomingExpenseCommitments` 把分期、账单、自动记账、待确认流水
   合成一个「未来义务」列表，去重规则是「分期优先」。

**没有的**：一条横跨模块的时间轴；也没有统一的「时间事件」词汇 —— 每个模块对
「什么时候发生」的定义、粒度、可编辑性都不一样。

---

## 二、深度分析：时间语义不是一个东西，是四类

这是整个设计的关键。把四类混成一张平表，用户必然误解。

### A. 事实（已经发生，不可再改语义）

流水、打卡记录、待办完成、加班记录、经期记录。

- 粒度：流水是**时刻**；打卡/经期/加班是**日**（记录里另有完成时刻）。
- 只读：点开看到的是已经发生的事；能编辑的是「记错了」，不是「改计划」。
- 不可重复：同一条记录不能因为在两个窗口里被查到就出现两次。

### B. 承诺（还没发生，但确定会发生）

待办的 `scheduledDate` / `dueAt`、打卡计划的提醒、分期待还期次、自动记账模板的
未来执行、账单提醒。

- 这是**投影**，不是记录：它随时会变（用户改了计划、账户余额不足导致不执行）。
- 点击去向应该是「规则」或「期次」，不是凭空造一个实例。
- 同一笔还款既是模板又是分期时只能算一次 —— 记账那边已经有这个去重（分期优先），
  时间线必须复用它，否则车贷会出现两次。

### C. 推断（统计预测，可能不成立）

下次经期、易孕窗、PMS。

- 必须**永远另设样式**并写明依据：经期预测是「按过去 N 个周期推算」，不是事实。
  混进事实里，用户会把预测当成日历。
- 不能参与「我该做什么」的计数（不能算成一条待办）。

### D. 容器（区间，不是点事件）

预算周期、薪水段、账单周期。

- 它们是「一段时间内的背景」，不是某天的一件事。在时间线上应该表现为**区间条**
  或日头部的背景标签，而不是一个点。

**结论**：时间线不是「把所有表 UNION 起来」。它是**四类语义各自成条，再按时间
排列**，并且每一类有自己的渲染、可编辑性与点击去向。

---

## 三、五个必须解决的冲突

| # | 冲突 | 后果 | 处理原则 |
|---|---|---|---|
| 1 | **粒度不一**（时刻 vs 日） | 把日粒度事件画到 14:30 会凭空造精度 | 事件带 `precision: day / minute`；日粒度只落在日分组，不出现在小时行 |
| 2 | **事实与承诺混排** | 用户以为「计划中的支出」已经花了 | 默认分区：已发生 / 待发生；即使合并流，也用不同底色与「计划」小标 |
| 3 | **重复规则 vs 实例** | 点「8 月 5 日的重复任务」进编辑，改的是整个规则 | 承诺类事件带 `ruleId`；点击时**先问意图**：改这一次 / 改规则 |
| 4 | **隐私与门禁** | 时间线把经期和金额暴露在未二次验证的页面上 | 时间线路由必须加入 `AppRoutes.sensitiveRoutes`；金额走 `MoneyPrivacy`；经期事件默认遮蔽，需解锁后显示 |
| 5 | **时区与日界** | 「昨晚 23:30 的流水」跑到今天 | 沿用既有约定：日粒度一律用 UTC date-key（`DateTime.utc(y,m,d)` 毫秒），时刻类按本地时区换算显示 |

另外一个隐性的：**去重键**。同一个「打卡 + 同日一笔健身消费」是两件事（事实与事实），
不能合并；但「分期期次 + 对应自动记账模板」是同一件事，必须合并。所以去重不能
一刀切，要按**事件身份**（`module:table:id` 或 `commitment:source:id`）判定。

## 四、方案

### 4.1 一个规范化的事件模型（只读，不落库）

```dart
TimelineEvent {
  id            // 'money:transaction:abc' / 'todo:task:xyz' / 'health:period:p1'
  occurredOn    // UTC date-key，日粒度归属的唯一依据
  at            // 可空：只有 precision == minute 才有值
  precision     // day | minute
  nature        // fact | commitment | prediction | container
  module        // money | todo | habit | health | lifeEnergy
  kind          // transaction / taskDue / planReminder / installmentDue /
                // cyclePredicted / salaryChange ...
  title, subtitle
  amountMinor?  // 仅财务类；显示前过 MoneyPrivacy
  emphasis      // normal | attention（逾期、大额、临近冷却截止）
  ruleId?       // 承诺类：由哪条规则/计划而来
  target        // 点击去哪：路由 + 参数（含「改这一次 / 改规则」）
  sensitive     // 是否需要解锁后才显示细节（经期、金额）
}
```

**不引入 `events` 表**，理由与「本月花掉不落快照」一致：事件是**派生视图**，
落库就要维护「什么时候重算」，而漏算一次的表现是「某天的事件凭空消失」，
用户查不出来。

### 4.2 每模块一个只读适配器

```dart
abstract class TimelineSource {
  String get module;
  /// 只查一个窗口；窗口由调用方给出（today / week / month），不提供「全部」。
  Future<List<TimelineEvent>> eventsFor(TimelineWindow window);
}
```

- `MoneyTimelineSource`：流水（事实）+ 未来义务（承诺，直接复用
  `upcomingExpenseCommitments`，连带复用它的去重）
- `TodoTimelineSource`：`scheduledDate` / `dueAt`（承诺）+ `completedAt`（事实）+ 重复实例
- `HabitTimelineSource`：打卡记录（事实）+ 计划提醒（承诺，由频率展开）
- `HealthTimelineSource`：经期记录（事实）+ `HealthCyclePrediction`（推断，另类）
- `LifeEnergyTimelineSource`：段起点（容器边界）、年终奖（年度）、加班（事实）、
  想买冷却截止（承诺）

聚合层做三件事：**按日分桶 → 每桶内按 nature 分区 → 桶内按时刻排序**。

### 4.3 三个出口，共用一份数据

| 出口 | 用途 | 内容 |
|---|---|---|
| **今日**（首页已有） | 现在该做什么 | 承诺为主 + 今天的事实，末尾「已完成」折叠 |
| **日程视图**（新） | 今天 / 本周要面对什么 | 日分组 + 事件点 + 区间条（预算周期、经期） |
| **回顾视图**（新） | 昨天 / 上月发生过什么 | 事实为主，推断单独一段，承诺只留「没做成的」（逾期/未执行） |

三者共用同一个 window 查询和同一套事件模型，只是过滤与排序不同。

### 4.4 「打通」的三个层次（不要一次都做）

1. **并列**（P0）：同一时间窗内的事件放在一起。这是用户现在最缺的。
2. **事件链**（P1）：计划 → 实例 → 结果。
   - 分期期次 → 自动记账执行 → 流水 → 预算占用
   - 打卡计划 → 当日记录（→ 若计划绑定了账户/分类，未来可关联一笔流水）
   - 待办 → 完成时刻 → 本周完成率
   链路只做**可点击的跳转**，不做自动建链。
3. **对照**（P2）：跨模块统计并列，如「本月经期周的花费 vs 非经期」。
   必须标注口径与样本量，且**只讲相关、不讲因果**——这是产品红线。

### 4.5 隐私与门禁（必须在第一版就做对）

- 把时间线路由登记进 `AppRoutes.sensitiveRoutes`（目前只有 `bookkeeping / health / gtd`）。
- 经期相关事件：未解锁时**标题也要遮蔽**（「经期」两个字本身也是信息）。
- 金额：走 `MoneyPrivacy.of(context)`，与其它页面一致，不新开一套遮蔽。
- 从时间线跳到模块页时，路由守卫照常生效（`redirect` 已按 sensitive 路径处理）。

### 4.6 性能与上限

- 只查窗口（一屏内最大一个月）；「无限下滑」不做，改为按月分页。
- 每个 source 的查询都必须走索引列：流水 `transaction_at`、待办 `scheduled_date`、
  打卡 `record_date`、经期 `start_date`。缺索引的先补。
- 单日事件上限（例如 50 条）+「还有 N 条」跳转到对应模块，避免一天几百笔流水把
  时间线撑爆。

## 五、分期交付

| 阶段 | 范围 | 验收 |
|---|---|---|
| **P0** | 事件模型 + 四个 source（记账/待办/打卡/经期）+ 今日/本周日程视图 + 门禁 | 打开本周：能看到分期到期、账单提醒、待办、打卡记录、经期预测；金额被遮蔽、经期未解锁时不显示 |
| **P1** | 事件链跳转 + 回顾视图（上月事实）+ 逾期/未执行单独分组 | 分期期次能跳到那笔流水；上月视图里没有承诺类事件混入 |
| **P2** | 对照类洞察（经期 vs 花费、完成率 vs 支出） | 每条洞察标出口径与样本量；不出现因果措辞 |
| **P3** | 时薪模块接入（段起点、年终奖、冷却截止） | 时间线上「涨薪」「年终奖入账」作为容器边界/年度事件出现 |

---

## 六、明确不做

- **不建 events 表**：派生视图，避免双写与重算时机问题。
- **不做无限历史滚动**：按月分页即可，全历史对「要面对什么」没有帮助。
- **不做跨模块因果结论**：「经期导致多花钱」这种话，样本和混杂因素都不支持。
- **不把推断当事实**：预测永远另设样式与文案，且不参与待办计数。
- **不新增输入**：时间线只读，唯一的新交互是「点进去改那一条」。

# 七、界面与交互

## 7.1 放在哪（信息架构）

**不加第六个底部模块。** 底部五个模块 + 「模块内面板」这套结构已经用满；时间线是
**横跨模块的视角**，塞进任何一个模块都名不正。

- **首页新增一个可插拔区块** `HomeBlockId.timeline`（`'timeline.week'`，默认可见）。
  它遵守首页既有注册表：用户能在首页编辑器里关掉、能拖顺序。
- **全屏页**：`/app/home/timeline`，从该区块的「本周」标题点进去；同时在首页
  「今日三宫格」下方给一行**紧凑条**（本次 1 条 + 今天剩余条数），不占一大块。
- **与既有界面分工**（不重复造）：

| 界面 | 视角 | 读写 |
|---|---|---|
| 首页三宫格 | 今日概览（钱/健康/行动各一格） | 只读，点进模块 |
| GTD 月历 | 任务/打卡的**可编辑**月视图 | 可编辑 |
| 记账未来现金流 | **钱的**视角，逐条义务 | 只读 |
| **时间线（新）** | 跨模块的**日**视角 | 只读 + 跳转 |

## 7.2 日程视图（主界面）

```
AppBar  时间线                      [筛选]  [今天]
─────────────────────────────────────────────────
[ 日程 ][ 回顾 ]                      ← 两个出口，分段控件
‹ 10 月 ›   日  一  二  三  四  五  六
            ●  ●● ●  ●  ●● ●  ○      ← 每天一个点，点大小=事件数，空心=无
─────────────────────────────────────────────────
▓ 预算周期 10/01 – 10/31 ▓            ← 容器：淡色区间带
┈ 经期（预测）10/20 – 10/24 ┈          ← 推断：虚线带
─────────────────────────────────────────────────
10 月 18 日 周六 · 待发生 3 · 已发生 4
  待发生
  ┌ 09:30 │ 🩺 体检预约           来自待办 · 计划 ›
  ├ 全天  │ 💳 房贷 ¥8,000        自动记账 25 日 · 承诺 ›
  └ 22:00 │ 🎯 降噪耳机冷却结束     想买 · 今天可以决定 ›
  已发生 (4)                                 ▾
```

**要点**

- **按日分组，组内分两区**（待发生 / 已发生）。已发生默认**折叠成一行**，
  展开才看到 —— 不折叠会让「今天还剩什么」被历史淹没。
- **日期条**：横向 7 天，每格一个点。点的大小表示条数（1–3 / 4–6 / >6 三档），
  空心表示没有事件。左右箭头切周。
- **容器带**（预算周期、经期）放在日期条下方，不参与行列表：它们是背景。
- 每区超过 6 条：显示前 6 条 + `还有 3 条 · 看待办`。

## 7.3 事件行（四层，和首页三宫格同一套语言）

```
│ 09:30   🩺  体检预约                     ›
│ 竖条    图标  来自待办 · [计划]  · 提醒 09:00
```

| 位置 | 内容 | 说明 |
|---|---|---|
| 左竖条 3px | 模块色 | 记账/健康/行动/时薪各一色，从 `colorScheme` 与 `moneyColors` 派生，不新引色板 |
| 左列 44px | `09:30` / `全天` | 日粒度事件写「全天」，**不编一个时刻** |
| 图标 20px | 模块内类别图标 | 复用现有图标表 |
| 主行 | 标题，单行省略 | 金额类带符号与正负色 |
| 副行 | 来源 · 性质标签 · 关键补充 | 12px，`onSurfaceVariant` |
| 右侧 | 箭头 / 逾期红点 / 完成勾 | 承诺逾期用 `moneyColors.expense` |

## 7.4 四类时间的视觉区分（不能靠文字解释）

| nature | 图标样式 | 额外标记 | 透明度 |
|---|---|---|---|
| 事实 | 实心 | 无 | 100% |
| 承诺 | 描边 | 右上「计划」10px 标签 | 100% |
| 推断 | 描边 | 「预测」标签 + **虚线**左侧竖条 | 70% |
| 容器 | — | 不出现在行里（顶部区间带） | 带 8% 填充 |

**规则：形态只能有三种以内**（实心/描边/虚线），否则变成图例考试。

## 7.5 回顾视图（第二段）

```
[ 日程 ][ 回顾 ]
‹ 2026 年 9 月 ›
本月：支出 ¥8,420 · 打卡 42 次 · 任务完成 18
10/31  支出 ¥1,240 · 打卡 3
10/30  支出 ¥0 · 任务完成 2
```

- 每天一行**摘要**，点击展开当天事件（只含事实）。
- 推断**不出现在回顾**里 —— 回顾是「发生过什么」。
- 顶部一条月统计，口径与各模块统计页一致（不要另算一套）。

## 7.6 交互

| 动作 | 结果 |
|---|---|
| 点整行 | 跳到来源（待办详情 / 流水详情 / 计划详情 / 健康日记录），带 `from=timeline` 以便返回 |
| 点承诺类且来自重复规则 | 先弹两行 sheet：**只改这一次** / **改整个规则** |
| 点容器带 | 跳到对应周期视图（预算详情 / 周期设置） |
| 点日期条某天 | 滚到那天并展开该天 |
| 左滑 | **不做**（时间线只读；而且上一轮刚把左滑动作改成大格子，不在这里重复） |
| 长按 | 不做 |

## 7.7 筛选

顶部「筛选」按钮 → 底部弹层：

- 模块：记账 / 健康 / 行动 / 时薪（默认全开）
- 性质：只看待发生（默认关）
- 不做时间范围选择（日期条已经承担了这件事）

## 7.8 隐私与失败态

- **未解锁时**：经期事件整行显示「健康 · 需解锁」，点行仍会走二次验证；
  财务事件的金额走 `MoneyPrivacy`（与全站一致）。
- **单个模块读取失败**：只在该模块的位置显示一行「读取失败 · 重试」，
  **不整页报错** —— 聚合四路数据，一个挂不能全挂。
- **空态**：今天没有安排 → 「今天没有安排」+ 两个按钮：加待办 / 记一笔。
- **首次进入**（时间线还没有任何数据来自某模块）：不显示该模块的图例，避免
  教用户一堆用不上的颜色。

## 7.9 布局约束（390 宽为基准）

- 事件行固定高度 56（两行文字），标题 1 行省略，副行 1 行省略。
- 时间列固定 44，避免日期的「全天」和「23:59」撑变。
- 日分组头 28；区间带 24。
- 一天的 12 条事件在 390×844 上不用滚动到底 —— 超出走「还有 N 条」。

## 7.10 验收（UI）

1. 390 宽下：单日 12 条不溢出；长标题被省略而不是换行顶高。
2. 未解锁：经期与金额都看不到内容，且点进去要二次验证。
3. 三种 nature 在实际字号（11–13px）下能区分，不依赖颜色（灰度下也能看出来）。
4. 四个模块里关掉任意一个：时间线不显示该模块，不报错。
5. 单个 source 抛错：其余三路照常渲染。
6. 从时间线跳到模块再返回：回到原来的日期位置（记住滚动与选中日）。

# 八、首页怎么办（与既有功能的边界）

## 8.1 首页现在是什么

两种布局，共用一套区块注册表（`HomeBlockId`，storageKey 不可改、可插拔）：

**横向分页（默认，4 页）**

| 页 | 内容 |
|---|---|
| 概览 | `board`（今日三宫格：钱/健康/行动）、`upNextCard`（接下来 3 条待办，可直接勾）、`alerts`（记账提醒横幅）、`insight`（跨模块洞察）、`quote` |
| 记账 | 预算 Hero、净资产、分类结构、最近流水 |
| 健康 | 周期状态、今日健康记录、未来 7 天预测 |
| 行动 | 今日待办、习惯打卡 |

**纵向列表**：同一批卡片按 `_section(0..7)` 顺次铺开，顺序与可见性由首页编辑器决定。

关键发现：**`HomeUpNextCard` 已经是「跨模块今日条目」的雏形**，只是它
只覆盖待办一类（`home_action_brief_providers.dart`），没有钱、没有健康、没有冷却期。

## 8.2 和时线间的重叠矩阵

| 首页现有块 | 与时间线的关系 | 结论 |
|---|---|---|
| `board` 三宫格 | 三个**数字**（预算余量 / 周期第几天 / 今日待办数），时间线给的是**条目** | **保留**，互补，不重复 |
| `upNextCard` 接下来 3 条待办 | 时间线的**子集**（只有待办、只有今天、可勾选） | **由时间线取代**（时间线块紧凑模式就是「接下来」，且覆盖四类） |
| `alerts` 记账提醒横幅 | 时间线会把分期 / 账单**逐条**列出来 | **收敛**：时间线可见时，alerts 只保留一行「今天 3 笔要付 · 看时间线」 |
| `insight` 跨模块洞察 | 统计层的结论（完成率、逾期数），不是事件 | **保留**，层不同 |
| 记账页（Hero/净资产/分类/最近流水） | 分模块的**可操作**视图 | **保留**，时间线只读 |
| 健康页（周期/今日/未来 7 天预测） | 预测会同时出现在时间线的区间带 | **保留**（首页是「预测说明」，时间线是「落在哪天」），但**文案与依据必须同源** |
| 行动页（待办 + 习惯） | 时间线的待发生区包含它们 | **保留**，可勾选/可编辑 |

一句话边界：**首页 = 分模块的、可就地操作的摘要；时间线 = 跨模块的、只读的日视图。**
两者不互相替代，只有 `upNextCard` 与 `alerts` 需要让位。

## 8.3 落地改动（最小集）

1. `HomeBlockId` 增加 `timeline('timeline.week', '本周时间线', HomeBlockModule.global, true)`。
   storageKey 一旦发布不可改，命名按「区块 + 时间跨度」。
2. **概览页**：`[board] → [timeline 紧凑] → [alerts 一行] → [insight] → [quote]`；
   移除 `upNextCard`（它的两件事——「看到接下来」和「就地勾选」——前者交给时间线，
   后者在行动页仍然有）。
3. **纵向列表**：在 `board` 之后插入一块，其余顺序不动。
4. **首页编辑器**：新块出现在列表里，可关。老用户的 `homeBlockOrder` JSON 里没有
   这个 key —— 解析时必须把缺失的块**追加到末尾**（现在的解析已经是按
   `HomeBlockId.values` 补齐，需要一条测试钉住，否则升级后新块可能不出现）。
5. 时间线块**紧凑模式**：最多 4 条 + 「查看全部」；点「查看全部」进全屏页。
6. `HomeStatusChips`（状态胶囊）与 `board` 的健康/行动格有既有重叠，**本轮不动**，
   单独记一笔债。

## 8.4 首页变长的风险

首页现在已经是 4 页 + 12 块。加一块的代价是概览页更长，所以：

- 概览页用**紧凑 4 条**，不是全屏列表；
- `upNextCard` 与 `alerts` 的让位抵消了大部分增量；
- 如果仍然过长，把 `insight` 挪到概览页末尾（它已经是末位，不再上移）。

## 8.5 验收

- 老用户升级：首页布局不变，新块出现在概览页 `board` 之后；关掉后重启仍是关。
- 概览页从 `board` 到 `timeline` 的滚动距离在 390×844 内不超过两屏。
- `upNextCard` 移除后，「就地勾选待办」仍能从行动页与时间线跳转完成（不丢功能）。
- `alerts` 与时间线不同时出现同一笔账单的双份条目。
