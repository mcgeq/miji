Miji · Bookkeeping · Pass 2

记账模块 · 第二轮复核（现代化 & 美观）

前两轮已经修掉了「用户做不到」的功能缺口与一批交互问题。这一轮换一个视角：把记账模块当成一个要「看起来现代、用起来顺手」的产品来体检。 结论先给：问题不在缺功能，而在「地基不统一」——4 套卡片容器并存、金额排版 93% 绕过统一组件、全局隐私只覆盖 2 个页面、加载态 26 处转圈只有 1 处骨架屏。 这些不是锦上添花，而是「同一屏里两种设计语言」的直接来源。
本文件只做诊断与设计稿，未改任何代码，确认后再进入实现。

先说清楚：前两轮已经落地的东西（本轮不再重复提）

避免「把已经做过的当成新问题」——下面是已实施清单，本轮诊断全部在这之外

一 · 地基不统一（本轮最大收益）

这些问题是「看不出哪里丑、但整体就是不够精致」的真正原因

1.3 图标风格不一致

分类图标 vs 界面其他图标

  • 1
    分类图标映射到 Material 基础版category_icon.dart 映射成 Icons.restaurant（直角版本），而界面其余 693 处用 _rounded 版本（Icons.flag_rounded）。分类格子里的图标会比旁边的操作图标「更硬」一点。
  • ?
    是否统一到 rounded可行（多数图标有 rounded 变体），但要逐个确认存在性，属于"细节但需要耐心"的改动。

1.4 没有动效语言

AnimatedSwitcher 0 处，无 PageTransitionsTheme

  • 1
    页面/面板切换是硬切记账 4 个主 tab + 「更多」切换、统计 5 个分页切换（分页有动画）、筛选结果刷新，都是瞬间替换。现代做法：内容淡入 + 轻微上移（150–200ms），列表入场错峰。
  • 2
    列表刷新无过渡筛选/排序后列表直接跳变，没有任何「正在换数据」的视觉提示（也没有骨架）。

1.5 触感反馈几乎没有

全仓 HapticFeedback 命中 1 处

  • 1
    该有触感的地方都没有拖拽排序落位、批量操作完成、左滑删除确认、金额输入、分页切换。移动端「高级感」有很大一部分来自这个。

二 · 功能缺口（用户能感知到的那种）

上一轮修的是「做不到」；这一轮是「有，但覆盖不全 / 藏在深一层」

2.1 金额隐私只覆盖 2 个页面功能

首页开关 + 账户页本地隐藏

  • 1
    统计 / 预算 / 分期 / 提醒 / 流水列表 / 流水详情 全部明文证据：隐私相关代码只出现在 home_money_text.dart、money_accounts_section.dart、account_selector.dart。用户在首页开了隐私模式，切到统计页金额全部暴露（在公共场所看账最容易翻车的地方）。
  • 2
    开关语义也不统一首页是 maskMoneyAmounts 偏好；账户页是 _hiddenAccountIds（按账户 id 存 SharedPreferences）。同一件事两套状态。
  • 建议
    一处开关，全局生效把 maskMoneyAmounts 提升为「全局金额遮罩」，统一走 MoneyAmountText(hidden:)；账户页的逐账户隐藏保留为进阶能力。

2.2 统计页的周期切换藏在抽屉里一致性

money_statistics_section.dart:122-140

  • 1
    流水页有日期胶囊（本周/本月/上月/自定义），统计页只有一行文字 + 筛选按钮同一个 App 里，「看某一段时间」的两套交互。统计页要换周期得：点筛选 → 找周期下拉 → 选 → 关抽屉，四步。
  • 2
    也没告诉用户「现在看的是哪一段」以外的东西头部只有 账本 · 本月，没有「与上月对比」「回到本月」这类快捷动作。

2.3 分期没有状态分组

  • 1
    进行中 / 已完成 / 已取消 混在一个列表卡内有状态胶囊，但已完成/取消的计划仍然占着首屏；isActive 只用来决定能不能取消。
  • 建议
    顶部状态分段 + 已完成默认折叠与提醒中心的「待处理/历史」、分类页的「已停用折叠」保持同一套语言。

2.4 预算卡 5 个操作全在左滑

  • 1
    查看流水 / 历史 / 分配 / 编辑 / 删除budget_card.dart 里 5 个 AppSwipeAction，PopupMenuButton 0 个。账户页上轮已补 ⋯，预算页没有 → 同一个 App 两套操作发现方式。
  • 2
    5 个左滑项在手机上一次只能看到 2–3 个需要横向滑动按钮条，命中率低。

2.5 四个列表页没有搜索

  • 1
    预算 / 分期 / 自动记账 / 提醒中心搜索框数量：0 / 0 / 0 / 0。分类页与流水页都有搜索，这四个没有；「我那张 24 期的白条在哪」只能滚。
  • 2
    分期与自动记账连筛选都没有AppFilterSheetTrigger 命中 0 处。

2.6 流水仍无多选与批量

  • 1
    月初整理上个月的零散记录只能一条条改这是上轮评审里唯一被跳过的项（当时判断改动较大）。提醒中心已经有多选模式可复用同一套交互。

2.7 「更多」面板只有 4 个入口

  • 1
    账本管理 / 结转 / 报表 / 记账设置 无处安放现在要进这些得绕：账本切换在顶栏胶囊里、报表在统计第 5 页、记账设置要去设置页。评审稿当初画的是 8 格。

三 · 观感细节（投入小、见效快）

这些改完，截图对比的差别最直观

3.1 加载态：26 处转圈 vs 1 处骨架屏

骨架屏只在首页存在（_HomeSkeleton / _SkeletonBox），没有抽成共享组件

  • 1
    记账模块所有列表加载都是居中转圈账户 / 流水 / 统计 / 分类 / 预算 / 分期 / 自动记账 / 提醒 共 26 处 CircularProgressIndicator。转圈让整页「白一下」，骨架屏让用户先看到结构。
  • 建议
    抽 AppSkeletonList / AppSkeletonCard复用首页已有实现，按页面套用 2–3 种骨架（列表行 / 卡片 / 图表块）。

3.2 下拉刷新只有 2 个页面

  • 1
    只有账户页与流水页接了 onRefresh统计 / 预算 / 分期 / 分类 / 提醒 / 自动记账 都没有。而记账数据会通过同步从别的设备过来，下拉刷新是「让数据变新」最直觉的手势。

3.3 图表基本是 fl_chart 默认外观

money_trend_chart.dart

  • 1
    没有圆角柱、没有渐变、没有入场动画、没有触摸提示关键 API 命中仅 2 处（BarChartRodData + 一处）。18 类卡片里图表占了 8 类，它们的「现代感」几乎完全由图表样式决定。
  • 建议
    统一图表语言圆角柱（borderRadius: 8）+ 纵向渐变（主色 → 透明）+ 首次入场 swapAnimationDuration + 长按显示当日数值的 BarTouchData/LineTouchData；配色统一走 moneyColors。

3.4 分类页：子分类 chips 墙

种子里 购物 23 个、居住缴费 16、娱乐 13、交通 11 个子分类

  • 1
    一张卡片里铺 23 个 chip分类页现在是「超长滚动 + 每几张卡里夹一面 chips 墙」。用户找不到目标，页面也显得杂乱。
  • 建议
    默认只展示 6 个 + 「+17 个」按钮展开卡片高度立刻降下来；展开后再编辑/排序。同时给分类页加「按用量排序」的默认视图（本月金额已经在卡片上显示了）。

四 · 内容层级（「更现代」的核心是信息架构，不是装饰）

同一个信息量，换一种编排方式，观感差别最大

4.1 统计页：28 张同构卡片

  • 1
    没有「先结论、后明细」的层次概览页顺序是：收支总计 → 收支趋势 → 消费变化。首页那种「一句话结论」的写法没有用到这里；18 类卡片全部同权重平铺。
  • 建议
    三层结构① 结论条（一句话，例如「本月支出比上月少 12%，主要是餐饮降了」）② Hero 数字 + 主图表 ③ 其余明细卡收进「更多分析」折叠区 / 按主题分区（消费结构 / 渠道 / 资产 / 预算）。

4.2 记一笔表单：14 个顶层区块

  • 1
    从「家庭账本」到「分摊设置」一口气排下来按 AppFormColumn 的 children 实测 14 个子控件（含条件区块）。虽然「更多信息」已折叠，但账户/分类/日期/支付方式/标签仍是全程展开的。
  • 建议
    把「标签」并入「更多信息」，日期默认显示为今天并收成一行紧凑选择目标：默认可见区块 ≤ 6 个（金额 / 账户 / 分类 / 日期 / 支付方式 / 更多信息），不牺牲能力。

✓ 修复：账户页的金额遮罩（用户反馈）

反馈：「全局遮罩打开后，在账户界面点击，无法展示遮罩的金额」——两个真实缺陷，都已修

状态缺陷原因与修法
已修逐账户「显示金额」在全局遮罩下失效状态模型缺一态：原来只有「显式隐藏」（_hiddenAccountIds）。全局遮罩打开时金额是隐藏的，但菜单根据显式集合判断，于是标签显示成「隐藏金额」、点下去也没有任何变化——用户看到的就是「点了没反应」。
改成三态：显式显示 > 显式隐藏 > 全局遮罩（新增 _revealedAccountIds，同样按 userId 持久化，key account_revealed_ids_<userId>）。菜单标签与「隐藏全部 / 显示全部」按钮都改成看生效状态，不再是单看显式集合。
已修全局开关用的是 ref.read_globalMasked 原来写成 ref.read(moneyAmountsMaskedProvider) —— 不建立依赖，账户面板不会因为开关变化而重建（当前只是被别的重建顺带救回来了，属于隐患）。改成在 build 里 ref.watch，语义正确且不依赖外壳是否重建。

Q1 · 全局金额遮罩要不要做

  • A
    只做「全局跟随首页开关」首页那个开关管全局，账户页保留逐账户隐藏。改动集中、语义清楚。我倾向 A。
  • B
    再加一个顶栏 👁 全局快捷按钮任何页面一键遮住，体验最好，但要在 5 个页面加同一套按钮 + 状态。

Q2 · 容器统一到什么程度

  • A
    只统一视觉让 4 套容器的圆角/边框/内边距都对齐到同一套 token（改动 ~120 处但都是参数级）。我倾向 A：收益 80%，风险最低。
  • B
    合并成 2 个组件彻底但要迁移 120 处调用点，回归面大。

Q3 · 金额排版是否全局启用 tabular

  • ?
    风险点等宽数字在部分中文字体下会让金额「略微变宽」，极窄屏（如 320dp）上长金额可能更容易溢出——需要真机看一眼再全量开。可以先在 MoneyAmountText 内默认开启，逐页检查溢出。

Q4 · 统计页做到哪一层

  • A
    只加周期胶囊 + 结论条改动小、收益明确。
  • B
    A + 分区折叠（消费结构 / 渠道 / 资产 / 预算）观感变化最大，但要重排 28 张卡的位置，回归面大。我倾向分两轮：先 A，看效果再决定 B。

Q5 · 预算卡要不要改环形进度

  • ?
    两种取向环形更好看、更「现代」，但信息密度比条状低一点（同样宽度下能放的数字更少）。如果预算卡本来就要减信息，环形很合适；如果想把「已用/剩余/日均」都留在卡上，条状更省空间。

Q6 · 本轮范围
