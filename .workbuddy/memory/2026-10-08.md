## 记账模块「家庭账本 + 均摊」记账失败问题排查

现象（用户反馈）：家庭账本 valuta 里设置均摊，参与/垫款人不是"我"（当前登录用户）时，记账提示"记录失败"，但流水已落库、无均摊数据；且"垫款人是我时，我也可以不参与均摊"。

排查结论（代码级，未改动代码）：

- 调用链：`TransactionFormDialog._submit` → `CurrentUserMoneyTransactionActions.createTransactionWithSplit`
  （providers:2513）→ `DriftMoneyRepository.createTransactionWithSplit`（data/parts/transactions.dart:55）。
- 流水与均摊在**同一个 drift 事务**内（transactions.dart:65-80），均摊失败会整体回滚。因此"流水在、均摊不在"
  只能由**事务提交之后**的失败造成：事务外还有 `_refreshBudgetSnapshotsForTransactionImpacts`(81)、
  `_syncCreditAccountRepaymentRemindersForAccounts`(91)、`_tryRebuildUsageStatsForUser`(94)，
  以及 provider 层的 `_rememberTransactionDefaults`(providers:2528)，它们抛异常时数据已落库且 `_refresh()` 不执行
  → UI 报"记录失败"且列表不刷新。
- 事务内唯一与"选了谁"有关的抛错点：`_createSplitForExistingTransaction`
  （drift_money_repository.dart:5019-5031）两处 `memberNotFound`（付款人/参与者须是该账本活跃成员）。
  UI 成员列表 `watchMembersForLedger` 与 repository `_membersForLedger` 过滤条件一致，正常不会不一致。
- 已确认的代码缺陷（待修）：
  1. 表单切换家庭账本（transaction_form_dialog.dart:300-307）只改 `_ledgerId`，未清空/校验 `_splitConfig`；
     而 providers:2518 用 `splitConfig.ledgerId` 覆盖 draft 账本 → 分摊配置可跨账本生效。
  2. 表单允许「待处理」状态（324-339）与分摊配置同时提交；status=pending 会在 4975-4983 抛
     `invalidSplitTransaction`，UI 无拦截。
  3. 事务外三步无容错，失败即误报"记录失败"且不刷新。
  4. 错误文案过粗（money_categories_section.dart:631 一律"记录失败"），掩盖 memberNotFound 等真实原因。
  5. 「垫款人可不参与分摊」是当前设计（需求 BR-12.1.6、提交 2ff44ec 放宽），但 UI 无提示，易误操作。

## 本轮实际改动（已落盘，7 个文件）

1. **data/drift_money_repository.dart**（+29）：新增 `_tryRefreshBudgetSnapshotsForTransactionImpacts`、
   `_trySyncCreditAccountRepaymentRemindersForAccounts`，放在 `_tryRebuildUsageStatsForUser` 旁边。
2. **data/parts/transactions.dart**：`createTransaction` 与 `createTransactionWithSplit` 事务提交后的
   预算快照刷新、还款提醒同步改用上面两个容错包装（已落库的写入不再被派生数据失败拖成"记录失败"）。
3. **providers/bookkeeping_providers.dart**：
   - `createTransactionWithSplit`：`_rememberTransactionDefaults` 包 try/catch，`_refresh` 必执行且补 `ledgerId`。
   - **`_draftWithLedger` 补回 `status` 与 `sourceTemplateRunId`**（此前漏传 status，draft 退回默认 completed，
     用户选「待处理」+分摊会被静默记成已完成 —— 这是一个真实 bug）。
4. **transaction_form_dialog.dart**：
   - 切换家庭账本 / 切到「待处理」时清空 `_splitConfig` + `_splitConfigAmountMinor`；
   - 待处理时分摊入口禁用并提示「待处理流水暂不支持分摊」；
   - 新增 `_splitConfigError()`：提交前校验 状态=已完成 / ledger 为家庭账本 / ledgerId 一致 /
     垫款人与参与者都还在当前账本成员里，给出具体中文错误而不是笼统失败。
5. **transaction_split_dialog.dart**：成员名后标「（垫款人）」；垫款人未参与时显示提示
   「垫款人未参与分摊，金额将全部由其他成员承担」。
6. **money_categories_section.dart**：`on MoneyRepositoryException` 不再返回固定「记录失败」，
   改调 `moneyTransactionActionErrorText(error)` 输出真实原因。
7. **money_quick_action_launcher.dart**：`_errorText` 补 `memberNotFound / activeSplitAlreadyExists /
   invalidSplitTransaction / invalidSplitAmount` 的分摊专属文案。

## 编译修复（用户跑 flutter build apk --release 反馈）

- 报错 `bookkeeping_providers.dart:2536: No named parameter with the name 'ledgerId'`：
  `CurrentUserMoneyTransactionActions._refresh` 原签名只有 `{String? transactionId}`（在类内 2740 行），
  与 `CurrentUserMoneySplitActions._refresh`（2477 行，带 ledgerId）不是同一个。
  修法：给事务类的 `_refresh` 加 `String? ledgerId`，非空时额外调
  `refreshAfterSplitChanged(transactionId:..., ledgerId:...)`（coordinator 的 bump 有微任务合并，不会重复重建）。
- 日志里的「migrate your plugin to Built-in Kotlin」只是 Flutter 的警告，不是构建失败原因。
