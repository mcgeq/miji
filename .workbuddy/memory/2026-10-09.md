# 2026-10-09

## 记账「提醒中心」处理不落流水的问题分析（仅分析，未改码）

结论：确实是设计与实现缺口，非偶发 bug。

- 链路：`_PendingReminderCard` 完成/左滑/批量 → `CurrentUserReminderCenterActions.complete`
  （bookkeeping_providers.dart:2000）→ `MoneyRepository.setReminderCenterState`
  → `DriftMoneyRepository._BillReminders.setReminderCenterState`（bill_reminders.dart:138）
  → 仅 upsert `moneyReminderCenterProcessing` 表 + 记 sync change，**完全不碰 moneyTransactions**。
- 附带缺口：
  1. 完成后不回写源头：`moneyBillReminders.status` 恒为 pending，`setBillReminderStatus(done)` 无 UI 调用点；
     分期 detail 仍为 pending，`postInstallmentDetail`（installments.dart:369，本身会正确生成流水）未被调用。
  2. 点卡片跳转不闭环：`recordTransaction` → `MoneyQuickActionLauncher.run(expense)` 打开**空白**表单，
     金额/账户/标题都不预填，提交后也不回写提醒状态。
  3. `actionType == openReminder` 分支是死代码（从未被生成），账单提醒点进去是记一笔而非编辑，注释与实现不符。
  4. itemKey 含 dueDate（`sourceType:sourceId:YYYY-MM-DD`），编辑提醒改日期后旧处理记录失效，已完成的提醒会复活。
- 现有测试 `drift_money_repository_reminder_center_test.dart` 只断言「移出待处理 + 进入历史」，未断言流水，
  即"不写流水"被当作期望行为固化，改动需同步更测试。

## 产出改造方案文档（未落码）

`docs/reminder-center-posting-fix-plan.md`。关键发现与方案要点：

- `MoneyBillReminderStatus.done` 全库零引用（纯漏实现）；`moneyBillReminders.relatedTransactionId`
  已存在且进 sync，**关联流水不需要 DB 迁移**。
- `TransferFormDialog` 已支持 initialToAccountId/initialAmountMinor/initialNotes
  （money_accounts_section.dart:1636-1640 的还款写法可直接复用）；
  但 `TransactionFormDialog` 不支持金额/描述/账户预填，且 description 硬编码为 `widget.type.label`（:875），需新增 prefill 入参。
- 重复提醒（repeatPeriodType）**没有**推进下一周期的逻辑 → 完成时不可置终态，否则下月失联。
- 方案分 6 阶段：A 完成回写源头 → 老数据处理 → B 支出型闭环 → C 分期走 postInstallmentDetail → D 还款走转账 → E 死分支清理。
- 待用户确认两点：(1) 是否保留「不记账只标记」入口（决策 2）；(2) 老数据中「已completed 但 reminder.status 仍 pending」的一次性修正。

## 用户决策 + 存量数据深挖

决策：① 不保留「不记账的完成」（完成必须产生流水，唯一出口是「忽略」，批量「完成」下线）；
② 存量数据需进一步分析。已按 ① 更新主方案文档。

### 存量数据专题结论（docs/reminder-center-legacy-data-analysis.md）

**关键认知修正**：这不是阶段 A 上线后的副作用，而是**当前正在发生的 bug**——
`MoneyBillReminderStatus.done` 全库零引用 → `isActive`（money_bill_reminder_entity.dart:123）恒为真 →

- 症状 1：系统通知停不下来。`scanNow()`(providers:1600) → currentUserBillRemindersProvider(:1126，
  底层 watchBillRemindersForUser **不带 status 过滤**) → scanAndNotify 只靠 isActive 判 skip；
  且 `_alertToken` 带 `od$overdueDays` → **逾期后逐日重复推送**。
- 症状 2：money_upcoming_bills_card.dart:37 同样只过滤 isActive → 「即将到期账单」金额虚高。
- 症状 3（潜在）：itemKey 含 dueDate，编辑日期后已完成的提醒会复活。

推荐「读取时自愈」而非一次性迁移：对齐既有惯例
`currentUserInstallmentPlansProvider`(providers:1389) 里 `repairInstallmentPlanStatuses` 的写法，
在 `currentUserBillRemindersProvider`:1148 前加 `repairBillReminderProcessingStatuses`。

### 两个必须排除的类别（硬约束，新发现）

- **repeatPeriodType != null**：置 done 会杀死下一期。
- **autoManaged == true（硬约束）**：`_syncCreditAccountRepaymentReminder`
  (drift_money_repository.dart:1196-1400) 会在**每一次流水写入**时（transactions.dart 有 7 处调用）
  把 status 重置回 pending（:1245/:1351）、把 relatedTransactionId 清成 null（:1244）。
  若 repair 与它互踢会导致 version 无限递增，必须整体排除。
  → 阶段 A 的 `setBillReminderStatus(done)` 与 `linkBillReminderTransaction` 都要跳过 autoManaged。
  好消息：这类提醒本就有正确终止路径——欠款归零时 `_deleteAutoManagedBillReminder` 会删掉它，
  即"真的记了还款流水"才是有效终止方式，与「完成=记账」的决策一致。

### 遗留限制 + 可选止血

周期性提醒无法用本次修正摆平（status 必须保持 pending 才能下一期出现），通知仍可能重复推。
可选「阶段 0.5」小补丁：把 scanNow() 里已算好的 pending 列表（:1624）传给通知服务过滤，十几行。
