## 编码约定（本项目 analyze 高频坑）

- **StatelessWidget 的私有辅助方法里不能用 `context`**（没有 `State.context`）。
  要主题就把 `BuildContext context` 作为第一个参数传进去。P5 的
  `_TransactionBulkActionBar._barButton` 就踩了这个（`undefined_identifier`）。
- `prefer_null_aware_operators`：`x == null ? null : x.y` → `x?.y`；若是
  `x == null ? null : () => x!()` 这类闭包，先 `final v = x;` 提局部再用。
- 写新 dart 文件后必须确认是 LF（Write 工具在 Windows 会写 CRLF），否则整文件被判改动。
- 提交前自查三件套：括号平衡脚本 + 新符号定义/引用计数 + `git diff` 逐文件复审
  （本机 `dart analyze`/`flutter analyze` 起不了子进程，Windows 管道句柄耗尽）。

## 记账模块重构分析（只分析，未改码）

通读 `lib/features/bookkeeping`（约 3.6 万行，9 个面板）+ 通知/首页看板/数据仓库，
产出优先级清单：

1. **提醒体系定时化**（最大坑）：`scanAndNotify` 只在 App 前台扫一次，没有任何
   `zonedSchedule` 预约通知；不打开 App 收不到任何账单提醒。另有通知只在 Android
   生效、无点击路由、无统一提醒设置、无每日记账提醒。
2. 待处理流水闭环：`MoneyTransactionQuery` 无 status/tag/金额区间字段，pending 流水
   记完无法筛出（不计统计、不占余额），等于记了就丢；流水无多选批量。
3. 记账表单：`_resolvedDescription` 恒为类型名（支出/收入），用户无法命名一笔账；
   `transaction_card.dart:176` 还有"过滤通用文案"的兜底逻辑佐证。无金额计算器。
4. 统计：16+ 张卡平铺一个长列表，无目录/折叠/自定义排序/下钻/导出；无独立对比卡。
5. 账户缺余额校正；预算卡缺"日均可用"。

## P1 提醒体系定时化（已开工）

新文件：
- `core/notifications/notification_tap_bus.dart` — 通知点击广播流（解耦插件回调与路由）
- `core/notifications/notification_providers.dart` — tapBus + appNotificationServiceProvider
  （从 bookkeeping_providers 挪过来，gtd 两个页面原本靠 bookkeeping_providers 间接引它）
- `features/bookkeeping/application/money_reminder_settings.dart` — 设置实体 + 按 userId
  存 SharedPreferences + AsyncNotifier
- `features/bookkeeping/application/money_reminder_scheduler.dart` — pending 项 → zonedSchedule
- `features/settings/presentation/money_reminder_settings_section.dart` — 设置 UI

关键设计决策：
- **调度源用提醒中心的 pending 列表**，不是 `bill_reminders` 表。后者的 `status` 恒为
  pending，是"处理完还天天推"的根因；提醒中心已聚合 5 种来源并吃掉完成/忽略/延后状态。
- 未来项（today < due - remindBeforeDays）→ 一次性精确提醒；窗口内/逾期 → 每天固定
  时间复推（`matchDateTimeComponents: time`），处理掉后下一轮同步自动取消。
- 每轮先 cancel 上一轮 id（prefs 存 CSV）再重排，上限 60 条，超出交给 daily digest。
- 同步入口做成被 App 根组件长期 watch 的 `moneyReminderScheduleSyncProvider`，而不是
  在各写入点手动调用——漏一处就会留僵尸通知。带签名比对避免空跑。
- 通知 id 独立号段 [700000000, 701000000)，避开预算/账单提醒的全区间 hash。
- payload 统一 `miji://money/<target>`（reminders / budgets / log）；早期塞实体 id，
  点通知只会冷启动。冷启动路径额外读 `getNotificationAppLaunchDetails()`。
- 每日记账提醒做成"每次同步重新布防的一次性提醒"（当天已有流水就不排），而不是每日
  重复——重复通知无法在触发时判断今天是否已记账。

## P4 analyze 收尾

用户 `dart analyze` 只剩 1 条 info：`money_comparison_card.dart:70`
`prefer_null_aware_operators`。修法不是只改那一行，而是把文件里三处
`x == null ? null : x.y` 全部改成「先提局部变量 + 判空」：
- `previous?.netMinor`（净额行）
- `final categoryTap = onCategoryTap;` 再 `categoryTap == null ? null : () => categoryTap(...)`
  顺带去掉 `!`（同一个 lint 在别的 analyzer 版本也会咬这种写法）
- `final previousMinor = row.previousMinor;` 再 `row.currentMinor - previousMinor`

**经验**：本项目开启了 `prefer_null_aware_operators`，写 `a == null ? null : a.b`
一律会被咬；`prefer_null_aware_operators` 只在「else 分支是同一表达式的成员访问」时
触发，但为了少一轮 analyze 往返，同类写法一次性全改。

## 环境坑

- Python `io.open(p,'w')` 在 Windows 上会把 `\n` 写成 `\r\n`，导致整个文件被判为
  全量改动。用脚本改完 dart 文件后要 `b.replace(b'\r\n', b'\n')` 回写 LF，
  否则 `git diff` 全是噪声（P1 的 main.dart / 两个 plan 页就中过）。
- **Write 工具在 Windows 上同样写 CRLF**：新建 dart 文件后也要转 LF
  （P5 的三个新文件都中过），改完用 `grep -c $'\r' file` 验证。
- 不要凭空猜 Material 图标名（`Icons.balance_rounded` 之类可能不存在）；
  先 `grep -rn "Icons.xxx" lib/` 看项目里有没有用过同类图标再决定。
- Flutter 此版本 `ReorderableListView.onReorder` 已弃用，换成 `onReorderItem`：
  后者 newIndex 是「移除旧项之后」的下标，正好是 `List.insert` 需要的语义。
- 本机 `flutter analyze` / `dart analyze` 起不了子进程（CreateFile failed 231，
  管道范例耗尽），sandbox 开关无效。只能靠人工核对 + 让用户跑 analyze。
- Riverpod 3.3.2：`AsyncValue` **没有** `valueOrNull`（home_page 自己写了扩展），
  用 `.value`；`AsyncNotifier` 自带 `update`，自定义方法不能同名。
- `num.clamp()` 返回 num，赋给 int 要 `.toInt()`。
