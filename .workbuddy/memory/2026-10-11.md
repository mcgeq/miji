## 预算「预占额度」分析（只分析，未改码）

用户诉求：月度消费预算应把自动记账任务的金额**预先占用**额度（含账户预算/分类预算），
按自动记账的「记账日期」判断是否落在当前预算周期内。

### 现状结论
- 预算已用 = `_budgetUsedAmountMinor()`（drift_money_repository.dart:2669），
  只 SUM **status=completed 且 transactionAt ∈ [周期起, 周期止)** 的流水。
  未来义务一律不占额度 → 月中"剩余额度"虚高，自动入账当天突然超支。
- **已有一版实现**：`getPendingAutoPostingAmountForBudget()`
  （data/parts/auto_posting.dart:471），展开模板在周期内 occurrence，run 未 posted
  即算待花；只被 `homeMonthBudgetSummaryProvider` 用（`used + pending`）。

### 该实现的 8 个问题（下次开发按这个清单改）
1. 只在首页用 → 预算页 / 统计页预算执行卡 / 超支提醒口径不一致（同一个预算两个数）。
2. 传的是首页自然月 scope，不是 `_budgetPeriodForBudget(budget, periodType)` 的周期
   → 账单周期/周/一次性预算会多算或漏算。
3. **`_autoPostingTemplateMatchesBudgetScope` 不比 `template.type` vs
   `budget.trackingType`** → 收入模板（工资）会预占支出预算。真 bug。
4. 不支持 scopeType=tag 的预算（模板无标签字段，必然匹配失败）。
5. 不校验 ledgerId。
6. 不校验 currencyCode，直接 `+= amountMinor`。
7. run 状态过粗：`userDeleted` / `blocked` 也算待花 → 虚占。
8. `watchBudgetsForUser` 只 watch moneyBudgets 表 → 改模板不触发首页重算。
   可用 `moneyDataRefreshVersionProvider` / `_watchMoneyDataRefresh` 兜底。

### 设计决策
- **拆两个数，不混成一个"已用"**：保持 `usedAmountMinor`（硬事实，供统计/历史/结转）
  不变；新增 `committedAmountMinor`（已预留，软事实），
  `可自由支配 = 额度 − 已用 − 已预留`。混在一起会无法核对、且把未发生渲染成已超支。
- **不写进 moneyBudgetSnapshots.usedAmountMinor** —— 快照是历史事实，写进去会污染
  历史趋势卡与 autoRollover 结转。实时算即可。
- 纳入的"未来义务"按确定性分层：自动记账未来 occurrence（scheduledFor）、
  分期未入账期（dueDate，最硬）、待确认流水（transactionAt，可开关）、
  账单提醒（dueDate，默认关，噪声大）。
- 周期判定一律复用 `_budgetPeriodForBudget(budget, periodType)`，不要另写一套。
- 项目无汇率换算能力（`exchangeRate` 无实现）→ 跨币种先跳过并留 TODO。

## 第三轮：分期 × 自动记账「重复登记」去重（方案一，代码已落地，待 analyze）

用户反馈：同一笔还款既建了分期、又建了自动记账模板 → 预算「已预留」被算两次。
**根因比表象严重**：`bookkeeping_providers.dart:172-176` 同一入口顺序跑
`executeDueAutoPostings` 和 `executeDueInstallmentPostings`，两套幂等键、两套账本，
到期当天**各建一笔真实流水**（余额扣两次、已用翻倍、列表两笔重复账）。
只改额度层是假修复：预留看着只算一遍，入账后照样翻两倍。

### 关键结论（以后别再走弯路）
- **分期本身就是自动记账**：`executeDueInstallmentPostings` 每天自动把到期期次入账。
  「再生成一个自动记账任务」不是新增能力，是换执行器。
- **不能让自动记账代持分期入账**：分期入账走
  `_MutableAccountLedger.postInstallmentExpense(principal, amount)` 释放冻结本金
  （`freezeCredit` 在 `createInstallmentPlan` 时已冻结全额本金）；自动记账走
  `applyTransactionCreate` → 冻结额度永不释放，信用卡可用额度永久错掉。
  另：等额本息/等额本金每期金额递减，固定金额模板天然对不上。
  → 唯一出口是**分期独占**，自动记账模板「被接管」而停用。
- **停用就能一次性解决两层**：`isActive=false` 的模板既不执行
  （`executeDueAutoPostings` 有 isActive 过滤）也不计入预算预留
  （`_loadCommitmentSources` 有 isActive 过滤）。不需要动任何幂等逻辑。

#### 机制澄清：分期入账的「支出账户」
- 分期入账流水**有**账户：`accountId` = 分期绑定的**信用账户**
  （`installments.dart:422` 用 `detail.accountId`；明细建时由 `draft.accountId` 写入，
  即 `money_installments_section.dart:1818` 的「信用账户」字段）。
  账本影响在 `_MutableAccountLedger.postInstallmentExpense`（`drift_money_repository.dart:443`）：
  减冻结额度 + 增已记账欠款 + 刷新可用余额。
- **易误读字段**：流水表 `actual_payer_account`（值为 `'installment'`）**不是账户 ID**，
  而是「付款标记」，取值 `default/transfer_out/transfer_in/installment`。
  仅用于 ①统计「来源」维度分类（分期/自动记账/手工）②`isInstallmentPosting` 识别禁改禁删。
  业务/UI 层从不把它当账户名展示。
- 分期入账流水在流水页**禁编辑/删除/退款/复制**（`money_transactions_section.dart:543-561`），
  账户也不可改——因为信用账户上冻结着该分期占用的额度，改账户会让冻结额度对不上。

#### 关键澄清：「分期 vs 自动记账」重复的**真正根因**
- 用户指出：分期记的是**支出**（消费分摊），还款记的是**转账**，两者语义不同。
  经核实成立：分期入账 `type: expense`（`installments.dart:415`）。
- **根因**：自动记账**只支持 `income`/`expense`，不支持 `transfer`**
  （表单只有「支出/收入」两项 `money_auto_postings_section.dart:1345-1350`；
  错误文案「自动记账仅支持收入或支出」:396；执行只走 `applyTransactionCreate`
  单账户单流水 `auto_posting.dart:757-786`）。
- 于是用户想「记每月还信用卡 1000」时**只能建支出模板** → 与分期第 N 期
  （同金额/同日/同账户）撞车 → 预算双算 + 到期记两笔。**重复不是天生的，是被逼出来的。**
- 若自动记账支持转账：转账天然**不占支出预算**（`budget_commitments` 已 `continue` 跳过）
  且**不会被冲突检测命中**（检测只认 expense）→ 是根治而非补丁。
  代价：模板需加 `toAccountId` + 表单加转账类型/转入账户 + 执行走 `applyTransactionTransfer`
  + DB 迁移（v25）。

#### 用户场景确认 + 账务硬约束（信用卡还款必须是转账）
- 用户确认：**分期入账 → 信用卡（expense）；自动记账 → 储蓄卡（expense，他用来记还款）**，
  期望这笔钱在预算/统计里**只算一次**。
- 账本事实（`_MutableAccountLedger`，`drift_money_repository.dart`）：
  - 信用卡（`isCreditLike`）+ `applyTransactionCreate(expense)` → `postedDebtMinor += amount`
    （**欠款增加**，:337-338）。
  - `applyTransferIncoming` → `postedDebtMinor -= amount`（**欠款冲销**，:392-395）。
- 因此把还款记成「储蓄卡 expense」有两个后果：
  ①支出预算/统计翻倍（用户已观察到）；
  ②**信用卡欠款永不释放**，还满 12 期仍显示欠满额、已用额度不减（更严重，用户可能没注意）。
- **正解**：还款记成**转账「储蓄卡 → 信用卡」**。转账天然不占支出预算 + 信用卡侧冲销欠款，
  支出只剩分期这一笔 → 「只算一次」且账务正确。
- 落地 = 上一条的「自动记账加转账类型」；这是唯一同时满足「只算一次」与「账务正确」的方案。
- **【用户决策】不做转账类型**。用户认定那个自动记账模板的**支出账户配错了**（挂储蓄卡，
  本应挂信用卡）：与分期同账户后即构成真重复 → **直接停用该模板**即可，支出只算分期一次。
- 关键约束（已核实 `auto_posting_conflicts.dart`）：冲突检测只查
  `isActive=true`(:146) 且 `type=expense`(:152) 的模板，且判定要求**同账户** →
  **账户配错时检测不命中**，这正是用户此前「预算双算却无冲突提示」的原因。
- 停用模板（`isActive=false`）后即：不执行 + 不进 `_loadCommitmentSources`
  （该查询过滤 `isActive=true`）→ 不占预算预留。**无需接管标记也能达成去重**。
- 【未修盲点】检测依赖"同账户"，账户配错会漏报。放宽（同日+同金额不看账户）可覆盖，
  但会误报（同日不同卡各消费同额）。待用户决定是否要做。
- 【用户决定】该盲点**不改**。

## 识图出错（release 包）根因定位与修复 —— R8 删掉了 ML Kit 的注册器构造器
**症状**：release APK 里点「截图记账」→ 提示「截图识别失败，请手动记一笔」（走了 catch 分支，即抛异常）。
**定位手段（关键，可复用）**：release 构建的 R8 产物就是证据库，不用连真机也能判：
- `build/app/outputs/mapping/release/usage.txt` = R8 **删掉**了什么
- `build/app/outputs/mapping/release/seeds.txt` = R8 **保留**了什么
- `configuration.txt` = 最终生效的规则（能看到我加的 -dontwarn 与 AAR 自带规则）
**根因**：three lines 躺在 usage.txt 里 ——
```
com.google.mlkit.common.internal.CommonComponentRegistrar:    public void <init>()
com.google.mlkit.vision.common.internal.VisionCommonRegistrar: public void <init>()
com.google.mlkit.vision.text.internal.TextRegistrar:           public void <init>()
```
ML Kit 用「合并 manifest 里的类名 + 反射无参构造」实例化 ComponentRegistrar，R8 静态分析看不见这条路径。
ML Kit 的 AAR 自带 consumer 规则 `-keep class * implements com.google.firebase.components.ComponentRegistrar`
—— **只保类、不保成员**，于是 R8 判定「没有字节码调用过这些构造器」就把它们删了 → 反射失败 → ML Kit 初始化失败
→ `TextRecognition.getClient()` 抛异常。seeds.txt 里这三个类**只有类名、没有成员**，正是这个现象（对比修复后应多出
一行 `TextRegistrar: TextRegistrar()`）。
**症状欺骗性**：debug 包一切正常（不跑 R8），**只有 release 会失效** —— 这类 bug 只能靠 release 实测或查 R8 产物发现。
**修复**（`android/app/proguard-rules.pro`）：加一条带**成员规格**的规则，比 `-keep class com.google.mlkit.** { *; }` 精确得多
（后者会为救一个构造器而关掉整个 ML Kit 的裁剪与混淆）：
```
-keep class * implements com.google.firebase.components.ComponentRegistrar { <init>(); }
```
**同时改代码**：`money_quick_action_launcher.dart` 的 catch 原来是 `catch (_)`，把真实异常吞了 —— 这次排查绕远路全因于此。
改为 `catch (error)`：`debugPrint` 完整异常 + toast 带 80 字内的原因摘要。另把「没能识别出金额，已打开空白表单」改为「请手动补全」。
**通用教训**：遇到「debug 正常 / release 失效」，第一反应查 `mapping/release/usage.txt` 与 `seeds.txt`，
并怀疑「反射入口 + keep 规则只保类不保成员」。

ML Kit 把那个 `¥`（大字号数字旁的小字形）认成别的东西 → ① 匹配不上；行里混进杂字 →
③ 的「整行纯数字」也作废 → 金额为空。

### 改法（`money_receipt_parser.dart`）
- 第 ③ 轮 `_plainAmountLine`（`^([-…])?\s*([0-9][0-9,]*\.[0-9]{1,2})$`）→ 换成
  `_decoratedAmountLine` = `^([^0-9]{0,4}?)([0-9][0-9,]*\.[0-9]{1,2})([^0-9]{0,4})$`
  ——判据从「整行是纯数字」改成「**剥掉前后各 ≤4 个非数字字符后是金额**」。
  符号被认成 `¥`/`￥`/`Y`/任意单字、甚至符号整段被吃掉只剩 `- 18.40`，都能捞回来。
- 放宽的代价用两条限制兜住：**必须带小数点**（裸整数一律不认）、**装饰里不许有数字**（`1000 18.40` 不认）。
- `_scanPlainAmount` → `_scanDecoratedAmount`；补 `_minusSigns` 常量。
- `_signOf` 从「只比对单个字符」改成「在整段前缀文本里找符号」——前缀现在是一整坨（`- ¥ ` / `-Y ` / 空）。
- 单测新增 group「金额行的装饰容错」6 例（6 种符号字形循环、只剩减号、切成两行、裸整数仍不认、
  两串数字不认、优惠/立减仍跳过）。本机用 dart2js + Node 跑探针 **26 项全过**（临时脚本已删）。
